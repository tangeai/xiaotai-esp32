# P4 开发指南

本指南适用于小钛 P4 1.4.1。首次体验直接下载 [16 MB 完整包](https://github.com/tangeai/xiaotai-esp32/releases/tag/esp32-p4-app-v1.4.1)，按[网页烧录说明](../../README.md#用浏览器烧录)写入，再完成配网和绑定。完整包会清除设备配置，请先备份；需要修改代码时，再看下方编译步骤。

## 准备源码与硬件

准备完整的 `waveshare-esp32p4-xiaotai/` 目录，以及：

- 微雪 ESP32-P4-WIFI6-Touch-LCD-3.5，16MB Flash，P4 芯片 rev 1.0–1.99。
- 配套屏幕、触摸、麦克风、扬声器和 OV5647 摄像头。
- USB 数据线、可联网的 Wi-Fi、手机及[小钛平台](https://xiaotai.chat/)账号。

源码已包含 SDK、模型、字体和提示音；首次编译由组件管理器下载其余依赖。版本和文件说明见[版本与依赖](DEPENDENCIES.md)。

P4 通过板载 C6 联网。本工程只烧录 P4；出厂 C6 能正常联网时保持原样。C6 固件异常时再查[C6 准备与恢复](C6_PREPARATION.md)。

## 编译与烧录

### 1. 打开 ESP-IDF 环境

按[官方安装指南](https://docs.espressif.com/projects/esp-idf/zh_CN/v5.5.4/esp32p4/get-started/index.html)安装 ESP-IDF 5.5.4，使用配套的 RISC-V 工具链，基线版本为 `14.2.0_20260121`。

Windows 打开安装器或 VS Code 扩展提供的 ESP-IDF PowerShell 终端。Linux/WSL 加载所安装 IDF 的 `export.sh`。进入 P4 工程目录后执行：

```sh
idf.py --version
python --version
riscv32-esp-elf-gcc --version
```

预期 IDF 显示 5.5.4，Python 和编译器均能运行。命令不存在时，先检查终端环境。

### 2. 编译

```sh
idf.py build
```

全新源码使用 `sdkconfig.defaults` 生成配置，无需复制别人的 `sdkconfig`。成功后应生成：

| 文件 | 用途 |
| --- | --- |
| `build/xiaotai_esp32p4.bin` | 应用镜像 |
| `build/xiaotai_esp32p4.elf` | 调试和回溯定位 |
| `build/flasher_args.json` | 本次完整烧录参数 |

SDK、产品链接符号和 I2C 驱动检查也应通过。链接后由 CMake 自动执行 `tools/check_firmware.cmake`，无需额外运行检查脚本。

若配置阶段报 `LV_USE_LIBJPEG_TURBO`、`LV_USE_LIBPNG` 或 `LV_USE_LZ4` 缺失，先按[组件版本检查误报](TESTING.md#组件版本检查误报)核对组件管理器版本，不要为此添加虚假的配置项。

已有目录的 `sdkconfig` 优先于 defaults。调整配置使用 `idf.py menuconfig`，有效值可在 `build/config/sdkconfig.json` 核对。Windows 与 WSL 切换构建时，保留需要的配置和日志后重新生成 `build/`，不要共用旧 CMake 缓存。

### 3. 确认串口

连接 P4 下载/调试接口，列出串口：

```sh
python -m serial.tools.list_ports -v
```

Windows 通常为 `COM数字`，Linux 通常为 `/dev/ttyACM数字` 或 `/dev/ttyUSB数字`。多块板同时连接时，通过逐块拔插识别。WSL 看不到 Windows 串口时，使用 Windows IDF 环境烧录，或先配置 USB 转发。

以下 `PORT` 均替换为实际端口。先读取芯片信息：

```sh
python -m esptool --port PORT chip_id
```

确认是 ESP32-P4，芯片修订在当前默认镜像接受的 rev 1.0–1.99 范围内。若显示 ESP32-C6，重新选择接口；其他 P4 修订需先适配配置与依赖，不能强制烧录。板卡 PCB 版本与芯片修订是不同的编号。

### 4. 烧录并查看启动

```sh
idf.py -p PORT flash monitor
```

IDF 按生成的参数写入 bootloader、分区表和应用。下载模式未自动进入时，按板卡 BOOT/RESET 步骤重试。退出日志监视使用 `Ctrl+]`。

启动日志应显示 `xiaotai_esp32p4`、版本 `1.4.1` 和本次 ELF 摘要，随后出现配网或已配置设备的页面。

**单独的应用 BIN 不能写到 0x0。** 日常使用上述完整烧录命令，保留 NVS 中的 Wi-Fi 和绑定信息。若旧固件分区不同，先比较[分区表](../partitions.csv)，不要直接整片擦除。

## 首次配网与绑定

### 1. 连接设备热点

没有已保存 Wi-Fi 时，设备显示“Wi-Fi 配网”。

1. 手机连接屏幕上的 `XiaoTai-XXXX` 热点，无密码。
2. 手机提示“无法上网”时，选择保持连接。
3. 浏览器访问 `http://192.168.6.1`，在附近网络列表中选择目标 Wi-Fi。
4. 输入密码，点击“保存并连接”。开放网络无需密码；隐藏网络使用“手动添加网络”。

设备记住最近成功联网的 4 个网络。选择标记“已保存”的网络后，名称自动填入、密码在设备端复用；密码有变更时点击“修改密码”。页面不显示或返回保存的密码。提交后先等待设备重启，再查看实际联网结果。

**预期结果：**设备获得 IP，开始检查绑定配置，热点关闭。手机此时切回正常 Wi-Fi 或移动网络。

已保存 Wi-Fi 的设备会自动连接。更换网络时，点击右上角的“…”更多操作按钮，选择“网络信息”后点击“断开当前连接”，再按上述步骤配网。手动断开后等待新配置；路由器临时掉线则自动重连。

### 2. 在平台填写六位验证码

联网且未绑定时，设备显示“绑定设备”和六位验证码。

1. 手机打开[小钛平台](https://xiaotai.chat/)，登录账号并进入设备管理。
2. 选择“添加设备”，填写设备上的六位验证码。
3. 按平台提示完成名称和绑定配置。

**预期结果：**平台列表出现该设备，设备进入首页。验证码填写在平台，不是在设备端输入。

设备上线后会自动上报实时查看、设备通话和微信通话的媒体能力，可在平台“我的设备 → 更多 → 设备信息”查看；无需手动填写。具体字段见[设备能力上报](P4_MEDIA_ARCHITECTURE.md#设备能力上报)。

显示 `------` 表示验证码尚未就绪；显示“绑定未完成”时可点右上角刷新。保留 NVS 的已绑定设备通常直接复用原配置，无需重新绑定。

每次开机联网后先同步时间，再进行绑定和 TiRTC 上线。网络需允许访问时间服务器；若停在此处，查看 `network clock` 日志，不要先清除绑定配置。首次绑定与已绑定设备都遵循这个顺序。

设备保留 DHCP 提供的 DNS，并在备用槽为空时补充 `223.5.5.5`。网络要求专用 DNS 或不允许公共 DNS 时，在 `XiaoTai application` 中修改 `CONFIG_XIAOTAI_FALLBACK_DNS_IPV4`，留空可禁用。备用地址不保证网络可达，具体诊断见[校时超时](TESTING.md#获得-ip-后校时超时)。

## 功能体验

先完成绑定，再按场景准备对端。每次通话结束后挂断，再进入下一项。

### AI 对讲

账号配置可用 AI 角色后，点击首页表情或说“你好小钛”。预期顶部状态变化，设备能听到问题并播放回答；字幕保留最新两行，AI 为淡蓝色，人声为淡绿色。

AI 播放时可以说话打断，结束时表达结束意图。打断、结束和情绪由云端识别并下发；设备没有独立的唤醒/休眠按钮。表情测试需要角色实际下发表情字段。

### 设备呼叫

1. 准备两台已绑定、在线的设备，在平台建立并接受联系人关系。
2. 进入“通讯录”，点导航栏同步图标。
3. 打开联系人详情，选择“语音呼叫”或“视频呼叫”，在对端接听。
4. 检查双向声音；视频通话还应检查画面和方向。挂断后再呼叫一次。

视频需要对端支持当前 P4 格式，详见[视频规格](P4_MEDIA_ARCHITECTURE.md#视频)。

### 微信通话

无微信联系人时，点击首页电话图标，微信扫码进入“小钛”小程序并完成设备及通话授权；再次点击二维码可关闭弹层。同步通讯录后应出现微信联系人。

- 设备呼手机：首页电话图标直接呼叫第一个微信联系人；指定联系人或选择视频时，从通讯录详情发起。
- 手机呼设备：在已授权的小程序中发起语音或视频通话，在设备上接听。

检查请求类型与界面一致，双方有声音，视频请求有画面，挂断后可再次呼叫。

### H5 实时查看

在平台选择设备的“实时查看”。浏览器应显示摄像头画面并播放设备声音。开启页面对讲并允许麦克风权限后，设备应播放浏览器采集的声音。

### 多人对讲

准备两台或更多已绑定、在线且支持多人对讲的设备，连接提供该功能的配套平台。这个入口是语音房间，不打开摄像头。

1. 在第一台设备点击右上角的“…”更多操作按钮，选择“多人对讲”（位于通讯录下方）。已有房间关系时直接连接该房间；没有时，选择“创建房间”。可留空密码，或设置 **4 位数字密码**，点击“确认”。
2. 等待页面显示 **6 位房间号**和“房间已连接”。在另一台设备选择“加入房间”，填写房间号及对应密码。
3. 两边均连接后，检查在线人数和成员名称。成员列表每页 3 人，用左右箭头翻页；右上角刷新图标用于重新同步。状态未就绪时会显示“成员状态待同步”，不要把旧列表当作实时结果。
4. **按住“按下讲话”发送语音，松开停止发送并继续收听。** 页面会显示“松开结束讲话”；成员状态区分“收听中”“麦克风开启”和“正在讲话”。麦克风被静音或房间未连接时不能讲话。
5. **返回菜单会断开对讲，不再收听或发送，保留房间关系。** 再次打开多人对讲时重新连接。要解除房间关系，点击右上角“退出房间”并确认；之后可以创建或加入其他房间。

房间输入使用三行四列数字键盘，只包含 0–9、退格和确认。本机显示平台下发的设备名称，未命名时显示设备 ID，后面标记“（本机）”；其他设备优先显示通讯录备注，没有备注则显示设备 ID。列表最多显示前 100 位成员，超过时页面会提示。

离开多人对讲页面后，不再自动续租、刷新成员或重连，不影响 AI、设备呼叫、微信和 H5 的原有入口。页面内断网会在网络恢复后重新连接；离开页面后则等到下次打开再连接。手指滑出按钮或连接变化会停止本次讲话，恢复连接后仍须重新按住按钮。断电可能需要等待服务端旧会话租约结束，详见[多人对讲排障](TESTING.md#多人对讲排障)。

### 其他交互

| 操作 | 预期结果 |
| --- | --- |
| 首页左右箭头、右上角“…”更多操作按钮 | 切换首页视图或打开更多功能 |
| “更多功能 → 待机表情”选择并应用 | 首页显示所选表情 |
| “设备设置”调节音量、麦克风和扬声器 | 状态与实际采集、播放一致 |
| 设置休屏时间、应答音 | 按所选设置运行 |
| 平台解绑后重新绑定 | 设备回到绑定页，Wi-Fi 保留，新绑定可同步联系人 |
| “更多功能 → 运行状态” | 查看资源、音频和事件信息 |

待机表情提供 23 种选择，包括“聆听”和“悠闲”。“思考”和“放松”固定使用第一套姿态，其余表情在进入时从两套姿态中选择；同一表情持续显示时不反复重启动作。对话中的聆听、思考状态优先展示对应表情，旧配置中已保存的表情编号保持有效。

## 配置服务

默认地址在 `idf.py menuconfig` 的 `XiaoTai application` 菜单中，定义见 [Kconfig.xiaotai](../main/Kconfig.xiaotai)。

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `CONFIG_XIAOTAI_DISCOVERY_URL` | `https://ep-open.tangeopen.com/services` | 获取平台、MQTT 和 TiRTC 服务地址 |
| `CONFIG_XIAOTAI_PORTAL_URL` | `https://xiaotai.chat/` | 设备上展示的绑定平台地址 |
| `CONFIG_XIAOTAI_DEVELOPMENT_CONSOLE` | 关闭 | 串口开发控制台，正常体验无需开启 |

使用默认平台不需要把开发者 AK/SK 写入固件。自建服务需实现发现、绑定、消息和通话接口；仅修改展示地址不会改变 API/MQTT 地址。

客户端只接受 HTTPS 服务发现，并要求返回的 HTTP/TiRTC 服务使用 HTTPS、MQTT 使用 MQTTS。TiRTC 直接使用同一次发现返回的 `tirtc-srv`，不会再由第二个固件配置指向另一套环境。自建服务需提供等价的 TLS 契约和受信证书链。

### AI 查询联系人插件

给 AI 角色添加设备动作 `query_contact_status`，通过 AI 命令通道的 `device_action` 调用。请求带可关联的 JSON-RPC `id`，查询只返回状态，不发起呼叫。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `target` | string，可选 | 联系人别名或设备 ID；空字符串查询列表 |
| `status_filter` | string，可选 | `online`、`offline`、`all`，默认 `online` |
| `ok` / `status` / `message` | boolean / string / string | 返回结果和说明 |
| `count` | string | 结果数量，按当前插件契约返回字符串 |
| `contacts` | array | 联系人列表 |

成功通过 `result` 返回，失败通过 `error` 返回。微信联系人按假定在线处理，不代表手机当时可接通。实现见 [starter_contact_query.inc](../components/starter_runtime/src/starter_contact_query.inc)。

## 遇到问题

| 停在哪一步 | 先检查 |
| --- | --- |
| 环境或编译失败 | IDF 版本、组件下载、有效配置；保留第一条错误，见[构建排障](TESTING.md#构建与启动) |
| 手机打不开配网页 | 是否仍连接设备热点；手动访问 `http://192.168.6.1` |
| 有 IP，但没有验证码 | “网络信息”的平台/消息状态，以及校时、DNS、HTTP、临时 MQTT 日志 |
| 平台已绑定，设备仍等待 | 绑定结果消息是否到达，设备是否确认；保留相关日志再处理 |
| AI、联系人或通话不工作 | 对照[业务排障](TESTING.md#业务与媒体)，先确认平台前置配置 |

当前 P4 是单麦克风加回采参考，AI 为语音场景；OTA、USB 麦克风和旧 Monitor 调试页不在功能范围。音视频格式、缓冲和内存说明见[系统架构](P4_MEDIA_ARCHITECTURE.md)。
