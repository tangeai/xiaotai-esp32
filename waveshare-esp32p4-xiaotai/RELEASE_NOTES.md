# 版本记录

## 1.2.0

- **唤醒模型**：更新模型与配套分类头，默认阈值为 0.90。更高阈值减少触发机会，也可能漏唤醒，可按环境调整。
- **首次体验**：配网和绑定页面独立刷新，及时显示热点信息与绑定码，不必等待通话服务就绪。
- **音频发送**：AEC 后上行增益由 6 dB 调为标称 9.52 dB，并保留限幅；唤醒输入、采集增益与 AEC 算法不变。
- **音频播放**：使用 ESP-DSP FIR 完成 8→16 kHz 重采样，保留跨包历史和尾音；按 15ms DMA 块供音，去掉重复软件等待，并将 DMA 待播量纳入自适应变速估计。
- **平台请求**：同站业务请求短时复用连接，空闲 3 秒后不再复用；错误、跨站与解绑关闭连接，不自动重放失败 POST。统一上报各业务实际音视频能力。
- **工程整理**：移除未使用的旧界面、业务与资源，保留当前页面、摄像头和视频通话；TiRTC SDK 2.3.0、Hosted/C6、视频配置和分区布局不变。

完整 16 MB 固件、烧录指南与校验文件见 [1.2.0 发布页](https://github.com/tangeai/xiaotai-esp32/releases/tag/esp32-p4-app-v1.2.0)。体验平台统一为 [xiaotai.chat](https://xiaotai.chat/)。完整包会清除配网、绑定和用户设置，请先备份。

本版作为受控网络体验固件提供，H5 播放调整已收到效果改善的实机体验反馈。唤醒阈值、全双工和弱网表现可结合实际环境继续验证。构建与运行证据分别见发布页，排障方法见[测试与排障](docs/TESTING.md)。

目标板：微雪 ESP32-P4-WIFI6-Touch-LCD-3.5。应用操作见[开发指南](docs/GETTING_STARTED_CN.md)，SDK 和配置见[版本与依赖](docs/DEPENDENCIES.md)。

## 1.1.2

本次公开更新包含 1.1.1 与 1.1.2 的改动，重点是配网体验、启动校时和表情动画。TiRTC SDK 保持 2.3.0，音视频配置与分区布局不变。

- **热点配网**：扫描附近 Wi-Fi，显示信号与加密状态，支持隐藏网络手填。设备记住最近 4 个成功联网的网络，再次选择时可复用密码；历史密码不返回浏览器。
- **启动校时**：每次开机联网后先完成 SNTP 同步，再开始绑定、鉴权和 TiRTC 上线。网络需允许访问时间服务器；备用 DNS 可配置或关闭，保留 DHCP 提供的解析地址。联网准备期间会提示设备尚未就绪。
- **表情动画**：提供 23 类表情、44 个姿态，增加聆听和悠闲，调整轮廓、眨眼与切换动作；思考和放松固定第一套姿态。
- **P4 扫描适配**：ESP-Hosted 主机侧核对扫描记录数量与缓冲容量，接受空列表；C6 固件与 RPC 协议保持不变。

完整 16 MB 固件、烧录指南和校验文件见 [1.1.2 发布页](https://github.com/tangeai/xiaotai-esp32/releases/tag/esp32-p4-app-v1.1.2)。完整包会清除配网、绑定和用户设置，请先备份。

配网页使用开放热点与 HTTP，网络记录未加密存储；请在可信环境中配网。构建与目标板运行验证分别以发布页记录为准。

## 1.1.0

相对本地 1.0.0 基线，增加多人对讲，完成工程独立化，并收口存储、内存和交互改动。下面区分本版新增内容与上一版已有功能。

### 多人对讲

- “更多功能”中，在通讯录下方增加多人对讲入口，支持创建房间、输入房间号加入、可选密码和确认退出。
- 展示房间号、在线人数、成员名称和麦克风状态，支持刷新与翻页；按下讲话、松开停发。本机显示平台名称或设备 ID，并标记“（本机）”；其他成员显示通讯录备注或设备 ID。
- 房间归属、SDK 连接和入房应答分开处理；重连默认关闭上行，旧连接不能恢复已经松开的 PTT。
- 返回菜单时关闭房间连接，停止收听、发送、心跳、成员刷新及自动重连，保留房间关系；再次打开后核对关系并重连。右上角“退出房间”用于解除房间关系，不影响其他应用。
- 房间号与密码使用三行四列数字键盘，仅保留 0–9、退格和确认，不改变 Wi-Fi 和联系人输入键盘。
- 断网退出保留旧会话释放事务，收到服务端结果后再申请新会话；断电仍受服务端旧租约约束。

操作步骤见[多人对讲](docs/GETTING_STARTED_CN.md#多人对讲)，责任层见[房间架构](docs/P4_MEDIA_ARCHITECTURE.md#多人对讲)。

### 存储、内存与交互

- 新增公共 `nvs_store`：读写统一交给内部 RAM 存储任务，参数快照和完成结果使用有界 PSRAM 池。保留原有键和保存失败语义，入队成功不等于已落盘。
- 设置页异步合并待保存值；配网和绑定在后台有界等待保存完成。业务任务不再直接执行 NVS 操作。
- 铃声和提示音使用常驻 PSRAM 栈；热点 DNS 和配网页任务按配网生命周期申请及回收。DMA、TCB、Flash 关缓存路径仍保留内部 RAM 要求。
- 建连时释放预留的连续内部内存，永久 MQTT 保持在线，不以停掉信令换取建连内存。
- 音量和静音改为非阻塞请求，由音频所有者应用；区分请求值、已应用值和硬件错误。UI 周期快照读锁失败时保留上一帧，不等待业务锁。

### 唤醒、诊断与工程

- 采集到唤醒改为有界 PCM 队列，窗口由推理任务处理；输入代次隔离暂停前的识别结果。TFLM 卷积适配补齐实际通道数，生成文件位于 build，不修改下载缓存或模型。
- 修正采集诊断 `age` 的时间戳竞争，避免新快照减去旧采样时刻产生无符号回绕；不改音频采样或处理节拍。
- AI 连接就绪后直接发起会话握手，移除固定 300ms 等待；仍须收到有效应答才开放音频。补齐 JSON 组包分配失败的所有权和清理检查。
- HTTP 方法、请求头和正文设置失败时立即返回原始错误，不发送不完整请求。增加低频排队、DNS、连接和响应等待诊断，不打印 token 或带身份的 URL。
- 保留播放收包/消费计数，帮助区分网络交付和本地播放；网络诊断不修改媒体、SDK 或自适应播放参数。
- P4 独立保存应用、资源、模型、配置和工具，移除对兄弟工程的构建引用。Windows 后处理继续使用 Python；补充独立依赖锁、卷积、NVS、内存和房间释放检查。
- 文档补齐多人对讲操作、存储所有权和排障路径；旧移植记录及私有调试资料不作为当前开发入口。
- 首页状态与两行唤醒提示使用同一待机条件，避免通话状态切换时显示“待唤醒”却没有提示。

TiRTC 保持 **2.3.0 P4 补丁库**，Hosted 主机补丁组件和 C6 固件未在本次版本收口中替换。原有 AEC、增益、编解码和自适应播放参数保持不变。

## 1.0.0 已有功能

以下为此前基线的功能概览，不重复计作 1.1.0 新增内容。

### 界面与操作

- 首页表情居中，顶部显示状态、时间、Wi-Fi 和三点菜单；字幕贴近底部，始终显示最新两行。
- 保留点击表情和语音唤醒，移除独立的唤醒、休眠按钮。
- 电话快捷入口位于右箭头下方，图标缩小、触摸区域扩大。有微信联系人时直接呼叫第一个联系人，否则显示小程序二维码。
- 通讯录支持同步、状态查询以及语音/视频选择。
- 首页背景中心轻微提亮、四周压暗；表情按受影响区域刷新，减少对触摸响应的影响。

### 配网与绑定

- 首次使用进入热点配网。手动断开 Wi-Fi 后等待重新配网；被动掉线自动重连。
- 热点门户只在 AP 接口开放，Wi-Fi 身份使用实际 STA MAC。
- 六位码在临时 MQTT 订阅确认后展示，不等待提示音结束。
- HTTP/MQTT 请求带身份代次，在线解绑由平台模块处理，避免旧结果影响新绑定。

### 音频与唤醒

- 使用 ES8311 单麦克风和 DAC 回采参考，接入官方 MR AEC、高通和数字自动增益。
- 上传增加一次带限幅的 +6 dB 增益，不改变硬件回采增益；实时与预录语音使用同一路处理。
- DSP 与媒体池就绪后启动采集。修正升采样的样本顺序，预录日志移出临界区。
- 下行解码和 I2S 播放分离，先归还接收槽，再分块消费 PCM。
- 按场景调整缓冲目标，以小幅变速处理欠载或积压，并支持尾音排空。
- 唤醒特征提取使用 P4 ANSI FFT，保留处理失败检查。

算法参数、缓冲容量和内存分配统一见[音频架构](docs/P4_MEDIA_ARCHITECTURE.md#音频采集)。

### 视频与通话

- AI 和纯语音会话不启动摄像头。视频通话保留 P4 的采集、编解码和显示流程。
- 微信呼入按媒体类型进入语音或视频界面；兼容字段缺省的现有处理不作为服务端正式接口定义。
- H5/微信上行使用 H264，微信下行使用 MJPEG；设备视频支持当前受限 baseline H264。
- 视频呈现与业务页面分开刷新，码率反馈交给视频模块执行。
- 视频资源初始化失败时按模块回收，避免跨层释放仍在使用的资源。

尺寸、帧率、码率和方向见[视频规格](docs/P4_MEDIA_ARCHITECTURE.md#视频)。

### 驱动与构建

- Hosted 同步 RPC 按 UID 和响应类型匹配，处理迟到、重复和错误类型响应。
- SDIO 初始化失败保留原始错误并回收已创建资源，WithCaps 任务使用配对删除接口。
- C6 关闭 modem sleep 并回读检查，SDIO 使用 4 线 40 MHz SDR。
- Windows 链接后检查改用 Python；依赖锁中的本机路径只生成在 build 目录。
- 保留 TiRTC 2.3.0 P4 补丁库，默认关闭串口开发控制台。

设备联系人、AI 角色和微信授权需要在配套平台完成配置，固件不会自动创建这些账号关系。
