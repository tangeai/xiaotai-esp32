# P4 Hosted 本地修正

供应商基线保持 ESP-Hosted 1.4.7，原提交 `d24d1dc3f709965fa61e3a1304c0896a9f3d497c`。没有整体升级组件、改动 C6 固件或协议字段；原版权和许可证保留。

## 同步 RPC 响应归属

2026-09-11 真机在获得 IP 后同时执行配网收尾和热点信息查询，出现请求映射失败，随后 `rpc_wifi_sta_get_ap_info` 复制空载荷并触发断言。原实现虽然按 UID 唤醒信号量，读取的却是全局响应 FIFO；不同任务的唤醒/消费顺序不保证等于回包顺序。UID 递增及同步表登记也未互斥。

本地修正位于 `host/drivers/rpc/core/rpc_core.c`：

- 使用原同步表保存各请求自己的响应，同时匹配 UID 和响应类型，移除全局同步响应 FIFO。
- 一个短临界区互斥锁保护 UID、登记、响应交接及退出。等待 C6 回复时不持锁，不串行阻塞音视频数据通道。
- 同步请求由调用者和 TX 线程共同持有，双方结束后才释放；超时后的迟到回复不进入下一个请求。
- RX 在锁内解除信号量引用，再由调用者释放，避免与超时回收竞争。
- 发送失败响应带回原 UID；提交队列失败、资源不足和业务失败继续返回失败，不伪装成功。
- 请求附属缓冲仅由发送/最终回收路径释放，不在入队后提前释放。

`host/drivers/rpc/slaveif/rpc_slave_if.c` 的入队失败日志改用调用点的消息常量，避免打印已被核心释放的请求。

未改变 TiRTC、AEC、采样率、码率、音视频缓冲或 UI Wi-Fi 调度。未扩大本次范围去重写原有异步 RPC 定时器；本应用 Wi-Fi wrapper 使用同步调用。

## SDIO 初始化失败与任务回收

本版纳入的初始化失败路径修正：

- `sdio_wrapper.c` 保留卡初始化/功能初始化的原始错误码；失败后释放卡和总线锁，清除卡指针。
- `sdio_read_task` 将错误交给 `transport_drv_reconfigure` 的调用任务回收，不再从 FreeRTOS 任务入口直接返回，也不自建清理任务。
- 仅在打开数据通道之前的卡初始化失败路径，调用任务取消四个 SDIO 工作任务，回收接收双缓冲、队列、信号量和 DMA 池。正常运行的 transport deinit 仍未完整实现，不据此声明运行中掉线能完全重建。
- `os_wrapper.c` 记录任务是否由 WithCaps 创建，对应使用正确的删除接口，保留原内部栈回退路径。修正 transport 层重复创建并覆盖总线锁的泄漏。
- Wi-Fi 初始化接口向上返回 transport 的实际错误，不将它变成 `ESP_ERROR_CHECK` 崩溃或成功。失败保持可见；没有新增自动复位、无限重试或降速兼容。
- SDIO 40MHz、C6 无线参数、RPC 协议和 TiRTC 库保持不变。

## 配网页扫描列表契约

`rpc_wrap.c` 的 `rpc_wifi_scan_get_ap_records` 现按 IDF 契约回填实际数量，并在复制前检查调用方容量及响应缓冲。原实现未回填数量，调用方可能继续按请求上限读取无效条目。

`rpc_rsp.c` 在分配/索引前校验 protobuf 数量与数组长度，检查空条目；成功的零条结果作为空列表返回，不再当作解析失败。这些改动仅涉及扫描结果，不修改 C6 固件、协议字段或音视频通道。

1.1.2 已通过 Windows / ESP-IDF 5.5.4 构建，以及主机扫描数量/容量、RPC 路由和初始化检查。C6 真机的扫描中重连、反复刷新、超时和配网退出尚未回归；主机桩不能替代这些时序证据。

## 验证边界

`tools/test_hosted_rpc_routing.py` 直接提取并编译实际 C 函数，使用 POSIX 线程/信号量和地址、未定义行为检查。旧核心可稳定复现“热点查询读到切换模式回复”；修改后覆盖并发、反序消费、超时、迟到、重复、错误类型、内存不足、队列失败和 UID 回绕。

Windows IDF 构建和主机检查通过不等于真机回归完成。当前真机发布状态以工程 `RELEASE_NOTES.md` 为准。控制表在 P4 上由 40 bytes 增至 120 bytes，另增加一个互斥锁，移除了原响应队列；运行时内部 RAM 净变化须实测，不用静态表差额冒充整机变化。
