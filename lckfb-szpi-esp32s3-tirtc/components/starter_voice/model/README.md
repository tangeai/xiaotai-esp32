# 唤醒模型

来源：用户于 2026-09-15 提供的 `nihaoxiaotai_v9.3_20260915_nhwc_tflite.zip`。
`nihaoxiaotai.tflite` 和 `head.h` 为同包配套参数，按原字节导入，必须一起替换。

| 文件 | 字节数 | SHA-256 |
| --- | ---: | --- |
| nihaoxiaotai.tflite | 67336 | `1dcfe29a10733ec272854bfbafb8a231f10bf3b0399cf6192cc08b38006fac78` |
| head.h | 17650 | `cc0364fa603a43c90d9de0b0fc39587c7c4d3350c3d1537b7018cf3a923d1a1e` |

输入由现有 16 kHz 单声道前处理生成，模型外部输入仍为 INT8 `[1,98,32]`，
内部卷积按 NHWC 排列；输出为 INT8 `[1,256]`，交给配套浮点 head 计算唤醒概率。
量化参数从模型张量读取，不硬编码。包内未提供新的 Mel 前处理或推荐阈值。
当前应用默认阈值为 0.900（按用户要求提高触发门槛），保留现有前处理和
160 ms 窗口推进量，不改 AEC、采集增益或播放。阈值提高会更难触发，也可能增加漏唤醒；
该参数的真机效果需重新实测，不能沿用 0.700 时的验收结果。

模型副本、128 KiB tensor arena 和 Mel 工作区仍显式分配到 PSRAM。
启动日志包含 `v9.3-20260915-nhwc`，并在宣布唤醒就绪前执行一次真实静音推理。
160 ms 是窗口推进目标，实际推理耗时以设备日志为准。

`tools/test_release_assets.py` 校验配对文件哈希；`tools/test_wake_model.py` 检查模型结构、
卷积通道及 head 数值边界。主机结构检查不能证明识别率、误唤醒率或板端推理速度。
