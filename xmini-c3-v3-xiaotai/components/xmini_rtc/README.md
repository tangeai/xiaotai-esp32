# PCMA RTC 适配层

`xmini_rtc` 在单一控制任务中调用 TiRTC SDK 并消费事件。SDK 回调只复制必要数据和更新有界状态，不在回调内执行 UI、HTTP 或阻塞媒体操作。音频接收方必须在回调返回前复制数据。

## 音频契约

| 项目 | 约束 |
| --- | --- |
| 编码 | G.711 A-law / PCMA，8 kHz、单声道 |
| 播放块 | 20 ms、160 字节 |
| 接收 | 按字节顺序重组输入，允许短块、拆分和聚合，不把传输包边界等同于播放块 |
| 发送许可 | 真实远端订阅，或业务握手成功后签发的代次/流许可；两者独立 |
| H5 上行 | 必须有真实远端订阅 |
| AI / GROUP | 使用流 1，由业务层核对格式和握手 |
| 设备 / H5 | 由业务 profile 选择流 10/11，不能只凭流号推断发送方向 |

本地 Subscribe 只开放接收，不制造远端订阅。不添加 Opus 或视频路径。取消、退订、换流、连接错误及退休会清除旧代次的部分帧；重新授权不能恢复已撤销许可的旧语音。

## 生命周期与所有权

- Start 前注册 PCMA 接收回调；`SYS_STARTED` 可能在 Start 返回前到达。
- WHIP/P2P 的 peer/token 输入由连接复制并持有，不能借用 UI 或 JSON 临时内存。
- 迟到成功与取消都由控制任务按连接代次处理；已关闭句柄只作为事件身份，不再解引用。
- 应用命令保留真实线格式和 SDK 返回值，不把旧业务命令统一改写为另一种逻辑编号。
- 消费命令事件后调用 `xmini_rtc_event_release()`；不能遗漏有主分配的释放。
- 普通挂断使用 Disconnect，不通过反复 Stop/Start 整个 SDK 监听器代替会话清理。

## 有界资源与失败语义

控制队列为 8 项，每项内联 511 字节；音频队列为 5 项。较大命令使用有主分配，单条上限 12 KiB，总预算 16 KiB。超限、分配失败、队列溢出及媒体格式不匹配均保留真实错误，不截断为有效消息或返回成功。

控制队列溢出会关闭新媒体入口，并由控制任务请求 SDK 停止；必须观察实际停止完成后才能 Uninit，不自动重启掩盖故障。过期排队语音会按当前延迟策略丢弃并记录，不宣称零丢帧。

## 验证边界

`tests/test_rtc.c` 使用实际适配代码、随附头文件与 mock SDK/队列，覆盖同步回调、异步输入复制、取消、代次、订阅、命令及接收边界。主机测试不执行 RISC-V SDK archive，也不证明 FreeRTOS 并发、真实播放、任意音频分片场景或异常网络表现。

当前 SDK 是项目专用体验构建，使用范围与文件身份见 [SDK 来源](../tirtc_sdk/PROVENANCE.md)。常规路径的板测不能扩展为 SDK 全量验收；群聊、弱网、长稳和声学效果仍需按实际集成场景验证。
