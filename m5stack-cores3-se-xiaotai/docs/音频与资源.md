# 音频链路与资源

本页用于定位音频节点和核对参数。首次体验见[开发指南](GETTING_STARTED_CN.md)，回归方法见[测试与验证](测试与验证.md)。下列值来自当前实现；任务栈单位均为**字节**。

本板的音频能力和使用边界见[开发指南](GETTING_STARTED_CN.md#本板音频与验证范围)与[已知限制](../KNOWN_LIMITATIONS.md)。

## AI 自动结束的尾音所有权

远端 `end_session` 表示 AI 会话结束，已进入本地抖动缓冲的 PCM 仍应播放完。
runtime 关闭连接并发起媒体排空，不阻塞等待；播放任务确认输入回调、队列、待写 PCM
和最后一次写入后的最大 90 ms DMA 窗口都结束后，再完成本地会话退出。
这段时间禁止新的上行和旧 AI 指令，但手动挂断、静音、来电抢占仍沿原路径立即生效。
等待上限为 7 秒，覆盖 32 个最大 1500 B A-law/8k 包约 6 秒音频、预缓冲和输出窗口；
超时会保留错误并退出，不报告成功。未引入新的音频缓存、任务或堆申请，新增内部状态为 16 B。
正常播放的 200/60/500 ms 缓冲范围、319/320/321 点变速、AEC 和增益不变。
相关用例为 `tools/test_ai_audio_drain.py`；验证步骤见[测试与验证](测试与验证.md)。

## 1. 采集链路

```text
ES7210 TDM：MIC1 / MIC3 / MIC2 / MIC4
              ↓ 重排
MR：人声麦克风 1 + 电气回采（麦克风 2 只统计电平）
              ↓
ESP-SR 单麦 FD AFE → 连续单声道 PCM → AGC
              ├─ 16 kHz Voicute 唤醒
              ├─ H5 / AI / Room：16→8 kHz → 20 ms PCMA 单声道上行
              └─ 设备互呼 / 微信：16 kHz、20 ms、Opus 单声道上行
```

MIC3 是扬声器电气回采，MIC4 不进入当前算法。I2S0 RX/TX 成对注册，共用 16 kHz 时钟。

AFE 使用 ESP-SR 2.5.0、`FD_LOW_COST`、滤波长度 4、`AGGR` NLP 和官方 WebRTC VAD，单麦输入不启用 SE。VAD 不裁掉静音输出，不重复拼接历史缓存，也不将未经消回声的原始麦克风混回输出。
此前的 MMR 双麦配置在 WakeNet 关闭时固定输出第一麦 NLP 平面；有限数字输入实测与 MR 输出逐样本相同，因此改为 MR。
feed 块变为 512 点（32 ms），输入池保持 256 ms 总时长（8 槽）。

AI 的 `start_session` 显式请求上下行 `g711a/8000/1`，同时接受服务器返回的等价名称
`alaw/8000/1`；采样率或声道不同仍拒绝启动。Room 单独协商，不修改设备互呼或微信的对端格式。

实现入口：[AEC](../components/starter_media/src/starter_aec.c)、[采集与播放](../components/starter_media/src/starter_media.c)、[AGC](../components/starter_media/src/starter_agc.c)。

### 增益放在哪一层

| 节点 | 当前值 | 调节原则 |
| --- | --- | --- |
| 人声模拟前级 | 24 dB | 为播放串入信号保留余量，避免 AEC 前削顶 |
| MIC3 回采 | 0 dB | 不随人声增益一起调整 |
| AFE 输出补偿 | 1.9952623 倍，约 +6 dB | 保留在 AEC 之后 |
| AFE 后 WebRTC AGC | 压缩增益 15 dB、目标 -6 dBFS、开启限幅 | 属于动态增益，并非每个采样固定放大 |
| 16 kHz 发送前增益 | +6 dB、目标 -3 dBFS | TX 编码前只处理一次，避免实时帧与预录帧重复增强 |

默认值见 [sdkconfig.defaults](../sdkconfig.defaults)，实际构建同时核对 `sdkconfig`。当前保留 AGGR 回声压制；改为更强档位前，先确认是否导致双讲发闷或吞字。声音小也应先检查 ADC、参考信号和 AFE 队列，再决定在哪层加增益。

## 2. 下行播放

AI、H5、设备与微信远程语音共用播放策略，本地提示音不参与变速。

```text
SDK 回调复制到固定池 → 自适应预缓冲 → H5/AI/Room PCMA 解码并升采样 / 设备互呼与微信 Opus 解码
  → 跨包 PCM → 319/320/321 点微调 → 有界 I2S 写入
```

实现：[starter_playout.c](../components/starter_media/src/starter_playout.c)、[参数定义](../components/starter_media/src/starter_playout.h)。

| 项目 | 当前策略 |
| --- | --- |
| 预缓冲 | 初始 200 ms，范围 60–500 ms |
| 抖动估计 | 到达间隔与媒体时间步长之差，按 1/16 平滑；目标为 60 ms + 4 倍估计值，按 20 ms 档位限幅 |
| 目标调整 | 晚到突发时较快增大；稳定约 10 秒后逐档减小 20 ms |
| 短句启动 | 最老帧到达等待期限也可开始，不必一直等待凑满目标 |
| 变速条件 | 时间戳有效且启动预热满足；水位计入排队、待写 PCM 和输出估算 |
| 变速幅度 | 每 20 ms 输出 320 点，消费 319/320/321 点，约 ±0.3125% |
| 变速迟滞 | 偏差约 ±60 ms 开始，回到约 ±20 ms 时退出 |
| 变速水位下限 | 120 ms，与预缓冲下限 60 ms 含义不同 |
| 尾音 | 保留跨包不足整块的 PCM；等待最多 60 ms，按实际长度写入 |
| 重新预缓冲 | 软件队列空且距写入超过 120 ms 时重新判断 |
| 淡入 | 开始或重新开始时 40 点，约 5 ms，不是每包淡入 |
| I2S 输出估算 | 上限 90 ms（6 × 240 / 16000），不是真实 DMA 游标 |

Opus 编码和解码任务栈分别为 48 KiB、24 KiB，均定向分配在 PSRAM。该尺寸以
`esp_audio_codec` 对编码器约 40 KiB、解码器约 20 KiB 的建议为下限，并为本工程
封装、诊断和发送调用预留余量。首个成功编码包和首个成功解码帧会打印任务栈
历史最小余量，用于真机确认，不以单纯“任务已创建”代替运行时证据。
编码器使用复杂度 0 的低 CPU 配置，保持 24 kbps CBR、20 ms 和 LOWDELAY 模式；
编码任务每处理一包主动让出 1 ms，避免连续积压时长期抢占界面任务。

缓冲吸收短时波动，变速修正水位漂移；两者不能补回永久丢失的数据。500 ms 是预缓冲上限，不是端到端时延上限；插值调速也不是保音高算法。

## 3. 保持连续性的约束

- SDK 回调只复制数据，播放任务负责 PCM 拼接和槽位归还。
- 应用按 SDK 交付顺序消费，不额外进行网络重排或重传。
- 输出暂存准备和 I2S 写入使用同一把锁。单次写入不超过 20 ms，释放后让出约 1 ms。
- 静音或会话切换推进 epoch，旧代次音频不进入新会话。
- ADC 读取与 AFE feed/fetch 分离；分别查询 feed/fetch 长度，不假定两者相等。
- 队满、格式错误、旧代次、写失败分别计数。无法确认部分写入进度时，不重播整块数据。

定位断续时同时观察帧龄、队列、锁等待和写入结果。软件队列空只能说明这一层暂时无数据，不能直接判定扬声器欠载。

## 4. 资源预算

| 对象 | 请求量 / 配置 | 位置 |
| --- | --- | --- |
| RX 固定池 | 32 × 1536 = 49,152 B；每槽载荷最多 1500 B | PSRAM |
| PCM 跨包暂存 | 970 B | 外部 BSS |
| 调速暂存 | 642 B，320 个 int16 采样及淡入状态 | 外部 BSS |
| 采集读取 | 4096 B 栈，CPU1，优先级 9 | PSRAM |
| AFE feed | 8192 B 栈，CPU1，优先级 7 | PSRAM |
| AFE fetch/下游 | 6144 B 栈，CPU0，优先级 7 | PSRAM |
| RX 播放 | 24576 B 栈，优先级 8 | PSRAM |
| TX 发送 | 49152 B 栈，优先级 7 | PSRAM |
| runtime | 24576 B 栈 | PSRAM |
| 业务启动/平台请求任务 | 13312 B 共用静态栈 | PSRAM，TCB 留在内部 |
| AFE 内部状态 | `INTERNAL_PSRAM_BALANCE` | 内部 RAM 与 PSRAM 混合 |
| I2S DMA、实时控制 | 由驱动申请 | 必要内部 RAM |

这些数值不包含全部 TCB、队列控制、驱动、SDK 任务、对齐和堆元数据。RX 池相比旧实现增加 36,992 B，也不能等同于总内存变化。

当前内部预留池为 131072 B，Quad PSRAM 的 XiP 关闭，Flash 使用 QIO/80 MHz。
预留池不等于已使用量；8 MB 也不等于可用堆。评估内存时分别记录内部空闲量、最大连续块、最低水位和 PSRAM。
