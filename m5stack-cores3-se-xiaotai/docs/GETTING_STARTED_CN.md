# CoreS3-Lite 开发指南

本指南适用于小钛 CoreS3-Lite 1.5.1。第一次体验按[首页的完整包烧录步骤](../README.md#用浏览器烧录)操作；准备二次开发时，再按本页编译源码。

## 准备源码与硬件

准备完整的 `m5stack-cores3-se-xiaotai/` 目录，以及 M5Stack CoreS3-Lite、USB 数据线、手机、2.4 GHz Wi-Fi 和[体验平台](https://xiaotai.chat/)账号。不要复制原立创板的 Octal PSRAM 配置。

源码已包含 SDK、模型、字体和提示音。首次编译会下载其余组件；保留 [sdkconfig.defaults](../sdkconfig.defaults) 和 [dependencies.lock](../dependencies.lock)，无需复制其他电脑的 `sdkconfig` 或 `build/`。

## 本板音频与验证范围

| 项目 | 当前实现 |
| --- | --- |
| 采集与回采 | ES7210 四槽 TDM，MIC1 为人声，MIC3 为扬声器电气回采；MIC2 只用于电平诊断 |
| 回声处理 | 官方 ESP-SR 2.5.0 单麦 MR AFE，16 kHz；没有双麦增强，不以双麦硬件数量推断算法能力 |
| 网络音频 | AI、H5、多人房间为 PCMA 8 kHz；设备和微信通话为 Opus 16 kHz，上行均为 20 ms |
| 播放 | 统一 16 kHz，初始缓冲 200 ms，自适应范围 60–500 ms，保留微幅调速 |
| 视频 | 板载 GC0308，仅用于 H5 MJPEG 查看；不提供视频通话或下行视频解码 |

部署条件与异常清理边界见[已知限制](../KNOWN_LIMITATIONS.md)。

## 编译与烧录

### 1. 打开 ESP-IDF 环境

按[官方安装指南](https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32s3/get-started/index.html)安装 ESP-IDF 5.5.4。Windows 打开对应版本的 ESP-IDF 终端；Linux/macOS 加载该版本的 `export.sh`。进入本工程目录后执行：

```sh
idf.py --version
xtensa-esp32s3-elf-gcc --version
```

预期 IDF 为 **5.5.4**，Xtensa GCC 为 **14.2.0 / esp-14.2.0_20260121**。本工程使用 TiRTC 2.5.0、LVGL 8.3.11 和 ESP-SR 2.5.0，其他依赖以锁文件为准。

### 2. 编译

首次配置新源码目录：

```sh
idf.py set-target esp32s3
idf.py build
```

看到 `Project build complete` 后，检查以下输出：

| 文件 | 用途 |
| --- | --- |
| `build/m5stack_cores3_se_xiaotai.bin` | 应用镜像 |
| `build/m5stack_cores3_se_xiaotai.elf` | 调试和回溯定位 |
| `build/flasher_args.json` | 本次完整烧录参数 |

日常修改只需 `idf.py build`。修改配置使用 `idf.py menuconfig`；已有 `sdkconfig` 优先于 defaults。Windows 构建后检查使用 Python，无需 Bash。Windows 与 WSL 切换时重新生成构建缓存，不共用旧 `build/`。

日常构建按依赖锁执行，默认关闭组件管理器的额外新版提示查询，保留依赖解析、下载与
校验。主动升级依赖时运行 `idf.py update-dependencies`，审阅锁文件变化后重新验证。
需要新版提示时，可显式设置环境变量 `IDF_COMPONENT_CHECK_NEW_VERSION=1`；组件管理器
2.4.9 的该查询可能误报未使用的 LVGL 9 配置缺失，本工程使用锁定的 LVGL 8.3.11。

### 3. 烧录并查看启动

连接 S3 下载/调试接口，列出串口：

```sh
python -m serial.tools.list_ports -v
```

将下面的 `PORT` 换成实际端口，如 Windows 的 `COM7` 或 Linux 的 `/dev/ttyACM0`。多块板同时连接时，先通过拔插区分端口，关闭占用它的监视器。

```sh
python -m esptool --port PORT chip_id
idf.py -p PORT flash monitor
```

先确认芯片是 ESP32-S3、MAC 对应 CoreS3-Lite，再执行烧录。下载失败时，长按 RST 约 3 秒进入下载模式，再重试；GPIO0 是音频时钟，不是 BOOT 按键。退出监视器使用 `Ctrl+]`。首次覆盖原厂固件前完整备份 Flash，并核对 NVS 分区边界。

**预期结果：**启动日志显示 `m5stack_cores3_se_xiaotai`、版本 `1.5.1` 和本次 ELF 摘要，屏幕进入配网、绑定或首页。

完整烧录使用 IDF 生成的参数。**单独的应用 BIN 不能写到 `0x0`**，当前应用地址为 `0x10000`。相同分区布局下正常烧录会保留 Wi-Fi 和绑定信息；迁入其他固件前先比较[分区表](../partitions.csv)，不要直接整片擦除。

## 首次配网与绑定

### 1. 连接设备热点

1. 手机连接屏幕上的 `XiaoTai-XXXX` 热点，无密码。
2. 提示“无法上网”时保持连接，浏览器打开 `http://192.168.6.1`。
3. 在“附近网络”点选目标 Wi-Fi，输入密码，点击“保存并连接”。开放网络无需密码；隐藏网络从“其他网络”手动填写。

页面显示信号和“已保存”标记，右上角可刷新扫描。最近 5 个成功连接的网络会保存在设备中，再次点选时自动选用保存的密码；密码已更改时点击“更换密码”。页面不显示或下载历史密码原文。

**预期结果：**设备重启后获得 IP，进入绑定检查。手机此时切回可上网的网络。保存成功只表示配置已写入，仍需等待联网；中文 Wi-Fi 名称最长为 32 个 UTF-8 字节。

已有配置会自动连接。更换网络时，在“三点菜单 → 网络信息”点击“断开当前连接”，再重新配网。手动断开后本次开机暂停回连；路由器临时掉线则自动重连。

### 2. 在平台填写六位验证码

1. 登录[体验平台](https://xiaotai.chat/)，打开设备页面。
2. 添加设备，填写屏幕显示的六位验证码，完成平台提示的配置。
3. 等待设备收到绑定确认。

**预期结果：**平台列表出现在线设备，设备进入首页。验证码填写在平台，设备端无需输入。

绑定页会显示平台网址，默认 `https://xiaotai.chat/`。自建部署在
`menuconfig → XiaoTai application → Device binding portal URL` 修改该引导地址，
它只影响屏幕和日志提示，不改变服务发现或 API 地址。

验证码失败或过期时，点击绑定页右上角重试，使用新验证码。保留 NVS 的已绑定设备会恢复原配置，无需重复绑定，也无需把设备密钥写入源码。

## 功能体验

先完成绑定和对应平台配置。每次通话结束后挂断，再进入下一项。双设备测试时分开放置，电脑端测试建议戴耳机。

### AI 对讲

为设备配置可用 AI 服务后，点击首页表情或短按电源键。进入聆听状态后说一句话，确认能听到回答；再短按电源键结束，用“你好小钛”测试语音唤醒。

字幕显示最新两行，人声淡绿、AI 淡蓝。对话表情依赖云端事件；首页没有独立的唤醒或休眠按钮。手动对话正常而语音唤醒不稳定时，先检查距离、语速和环境噪声。

### 设备呼叫

1. 准备两台已绑定、在线的设备，在平台建立并接受联系人关系。
2. 打开“三点菜单 → 通讯录”，点右上角刷新图标。
3. 选择联系人，进入详情并点击“语音呼叫”，在对端接听。
4. 检查双向声音，挂断后从另一端回拨。

两台设备连接同一个 Wi-Fi，并不代表已经获得互呼授权。

### 多人对讲

准备两台或更多已绑定、在线且支持多人对讲的设备，使用支持房间功能的平台服务。

1. 打开“三点菜单 → 多人对讲”。如果平台已经为设备分配房间，会直接连接该房间。
2. 尚未入房时，在一台设备上点击“创建房间”；密码可留空，也可设置四位数字密码。
3. 其他设备点击“加入房间”，输入同一个六位房间号及对应密码。房间号开头的零需要保留。
4. 等待显示“收听中”，按住底部按钮讲话，松开后继续收听。成员较多时使用左右翻页按钮。

本机优先显示平台下发的设备名称，后加“（本机）”；未命名时显示设备 ID。其他成员优先显示通讯录备注，没有备注则显示设备 ID。

| 离开方式 | 结果 |
| --- | --- |
| 左上角返回菜单 | 停止房间收发并断开连接，保留房间归属；再次打开多人对讲时重连 |
| 右上角“退出房间” | 解除本机的房间归属，返回创建/加入页面 |

房间应用关闭后不在后台轮询或自动重连，也不会占用其他应用的通话连接。重启后需要重新打开多人对讲页面才会入房。

### 微信通话

没有微信联系人时，点击首页绿色电话图标，扫码进入小程序并完成设备通话授权；再次点击二维码可关闭弹层。刷新通讯录后应出现微信联系人。

- 设备呼手机：首页电话图标直接呼叫**第一个微信联系人**；指定其他联系人时从通讯录发起。
- 手机呼设备：在已授权的小程序设备列表发起通话，在设备上接听。

检查双向声音，挂断后再次呼叫。扫码进入小程序不等于完成授权；微信联系人没有普通设备式的实时在线状态。

### H5 查看与对讲

1. 在平台设备列表打开实时查看，检查摄像头画面；开启声音，检查设备麦克风上行。
2. 允许浏览器麦克风权限后，使用页面“按住说话”，检查设备扬声器播放。
3. 在设备端点击“结束查看”，或在网页端断开，确认查看会话结束；再打开一次或切换到 AI 对话，检查音频资源是否正常交接。

GC0308 仅在当前查看会话收到 stream 11 的订阅后启动采集。关闭视频订阅或结束查看后，驱动、编码器和帧缓冲由摄像头 worker 释放；音频仍由原会话所有权控制。
1.5.1 已完成本板手机 H5 画面、音频收发及重复进入/退出的针对性验证。12 fps 是发送节拍目标，拥塞时优先丢弃视频帧；实际声音、弱网和长期运行仍需按使用环境验收。

## 配置服务

使用默认平台无需把开发者 AK/SK 写入固件。自建服务时，在 `idf.py menuconfig` 的 `XiaoTai application` 菜单调整配置，定义见 [Kconfig.projbuild](../main/Kconfig.projbuild)。

| 配置 | 用途 |
| --- | --- |
| `CONFIG_XIAOTAI_DISCOVERY_URL` | 默认 `http://ep-open.tangeopen.com/services`，获取 API、MQTT 和 TiRTC 地址 |
| `CONFIG_XIAOTAI_PORTAL_URL` | 默认 `https://xiaotai.chat/`，只改变屏幕和日志中的绑定网址 |
| `CONFIG_XIAOTAI_DEVELOPMENT_CONSOLE` | USB 串口开发控制台，本板 defaults 开启；关闭后 AT 不可用，触摸和电源键不受此开关控制 |

默认方案用于受控网络评估。生产部署前检查[网络与凭据风险](../KNOWN_LIMITATIONS.md#网络与凭据)，仅改变绑定网址不会改变业务服务地址。

协议参考：[AI 集成](https://docs.tange.ai/products/ai-chat/guides/device-integration.html)、[设备互呼](https://github.com/tangeai/tirtc-server-example/blob/main/thing-connect/device-call.md)、[H5 对讲](https://github.com/tangeai/tirtc-server-example/blob/main/thing-connect/device-h5-live.md)、[服务端部署](https://github.com/tangeai/tirtc-server-example/tree/main/thing-connect)。

## 遇到问题

| 停在哪一步 | 先检查 |
| --- | --- |
| 找不到命令、编译失败 | IDF 版本、组件下载和第一条错误；Windows 若仍调用旧 Bash，执行 `idf.py reconfigure` |
| 串口打不开、烧录超时 | 数据线、端口占用、芯片类型和下载模式 |
| 打不开配网页、保存后连不上 | 手机是否保持热点连接；目标 SSID、密码和 2.4 GHz 网络是否正确 |
| 扫描提示设备正在连接 | 当前连接尝试优先，不会为了扫描中断连接；稍后点击刷新，或手动填写网络 |
| 已保存密码不可用 | 重新输入密码；只有成功获得 IP 的网络才进入历史，旧固件不会留下多网络历史 |
| 配网返回 500 / 503 | 500 为存储失败；503 为重启处理不可用或已有请求，保留日志，避免连续提交 |
| 有 IP，但没有验证码或绑定确认 | 网络信息中的平台、消息服务状态，以及发现、HTTP、MQTT 日志 |
| AI 无回复、联系人为空或呼叫失败 | AI 服务配置、联系人关系、微信授权和对端状态，再核对失败日志 |
| H5 能听但不能说 | 浏览器麦克风权限、输入设备和“按住说话”状态 |
| H5 已连接但没有画面 | 检查设备型号为 CoreS3-Lite、平台视频能力上报、stream 11 订阅和 `view_camera` 错误；双向音频需分别确认 |
| 声音断续、回声或音量小 | 先取消弱网注入，分开检查上下行，保留日志和录音后再调参 |

二次开发见[架构与代码入口](../ARCHITECTURE.md)，检查命令见[工具说明](../tools/README.md)。
