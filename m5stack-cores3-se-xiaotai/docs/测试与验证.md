# 测试与验证

先按[开发指南](GETTING_STARTED_CN.md)完成基本体验，再根据改动选择回归范围。下面是二次开发的检查方法，按影响范围选择用例；同一输入的有效结果可复用。

## 按改动选择检查

| 修改范围 | 先做的检查 | 设备上再验证 |
| --- | --- | --- |
| 文档、文件整理 | 变化的链接、引用和 Git 差异；资源/SDK 变化才核对相关哈希 | 运行输入未变时不编译、不做设备回归 |
| 仅版本号 | 增量构建、镜像版本 | 不单独要求全量业务回归 |
| 配网、NVS | `test_wifi_credentials.py` 及配网相关主机用例 | 旧配置启动、修改网络、重复提交、主动断开与重连 |
| 联系人、会话状态 | 联系人查询、绑定、房间恢复及任务清理用例 | 来电/去电、拒绝、取消、挂断、第二通和会话切换 |
| 多人对讲 | `test_room.py`、`test_room_ui.py` | 创建/加入、按住/松开、成员分页、返回重进与明确退出 |
| 采集、AEC、播放 | 采集增益、重采样、播放队列及媒体契约用例 | AI、H5、设备、微信及多人对讲，检查双讲、尾音、弱网和录音 |
| 首页、字幕、表情 | UI 规则与事件生命周期检查 | 页面切换、动态字幕、所有表情、边缘触摸 |
| 校时与云端启动 | `test_clock_fallback.py`、启动顺序规则 | 已绑定/未绑定冷启动、复位保留时间、NTP 不可达及恢复；确认校时成功先于 TiRTC 初始化 |
| SDK、工具链、依赖或 ABI | 构建与全量主机回归；有明确原因才清理缓存 | 所有受影响业务、重复操作与长时间运行 |
| 字体、图片、模型 | 构建及对应资源、渲染或模型用例；涉及公共逻辑时扩大范围 | 实际显示或识别效果，不用静态通过替代 |

主机检查验证部分实际函数与模拟依赖；设备检查验证真实时序、外设和效果。两者分开记录。

定向回归直接运行现有脚本，不新增另一套测试入口。例如只改房间 UI 时，在已准备依赖的 Linux/WSL 环境执行：

```sh
python3 tools/test_room_ui.py
python3 tools/test_ui_routes.py
python3 tools/test_screen_event_lifetime.py
```

如果同时改变房间状态机或媒体门控，补 `test_room.py` 及对应媒体用例；采集/AEC、全局内存、公共生命周期等不能只跑 UI 用例。表格是选择起点，最终范围按实际 diff 与调用关系决定。只有 SDK/工具链等广泛变化、影响不清或用户要求时，才运行 `bash tools/run_host_tests.sh` 全量入口。复用结果时核对源码、配置、工具链和依赖身份。

## 开始前记录

记录源码 commit 和未提交改动、工具链/SDK/配置、板卡与串口、设备 ELF 身份、网络及对端版本。日志和录音放仓外，分享前去掉密码、token 和设备密钥。

最小记录格式：

```text
源码与镜像：
条件与操作：
预期：
实际结果与日志位置：
未覆盖：
```

固件构建和主机工具用法见 [tools/README](../tools/README.md)。修改前后尽量使用相同操作与网络条件，不同时调整多组参数。

## 设备最小回归

保留现有 NVS，不默认整片擦除。首次绑定、真实掉电写入等破坏性实验应使用可恢复的测试设备和凭据。

| 环节 | 操作 | 应观察到的结果 |
| --- | --- | --- |
| 启动 | 正常上电 | 版本正确，音频任务就绪，无异常复位 |
| 配网 | 提交新网络并等待重启 | 新配置成对生效；未联网停留配网页，联网后关闭配网服务 |
| 保存失败 | 在主机模拟 NVS 错误 | 接口返回失败，不出现新旧 SSID/密码混用 |
| 浏览器退出 | 提交网络后关闭网页 | 已接纳的配置仍被应用 |
| 重连 | 暂停已保存的 AP，再恢复 | 退避重试并恢复连接 |
| 主动断开 | 点击“断开当前连接” | 打开配网，本次开机不立即回连；凭据仍保留 |
| 绑定 | 获取验证码并完成绑定 | 当前确认生效，取消后续提示音并进入首页 |
| 联系人 | 同步、改名、网络下发查询 | 内容和应答对应，键盘及中文正常 |
| AI | 首句、双讲、结束、再次唤醒 | 双向音频与字幕正常，旧帧不进入新会话 |
| 设备/微信通话 | 双向发起，接听、拒绝、取消、挂断，再次呼叫 | 状态一致，第二通可用，无意外挂断 |
| H5 | 监听、按住说话、退出，再开 AI | 双向音频有效，会话可切换 |
| 多人对讲 | 入房、按住/松开、返回菜单再进入、退出房间 | 返回只断连，退出解除归属；松手停止上行，不占用其他应用连接 |
| 页面 | 表情、字幕、音量、菜单与边缘点击 | 显示完整，交互不被长时间阻塞 |
| 内存 | 重复同一流程，在相同待机状态采样 | 比较内部 free/largest/min 与 PSRAM，区分首次分配和持续泄漏 |

配网主机用例还覆盖旧格式读取、未知版本、错误长度、最大输入、分段 HTTP、500/503、
重复请求和“写入后才报错”等分支。HTTP 错误响应成功发出，不等于业务保存成功。
这些模拟不能代替真实 Flash 掉电恢复或任务栈余量测量。

## 音频与弱网

先在正常网络下确认听感，再每次只增加一种扰动。以下是**建议测试条件，不是已完成的实测结果**：

| 条件 | 建议起点 | 重点 |
| --- | --- | --- |
| 正常网络 | 无额外注入 | 建连、首音、持续播放、UI 响应 |
| 固定延迟 | 单向 50 / 100 ms | 将首音等待与播放中断分开 |
| 抖动 | 在固定延迟上增加 20 / 50 ms 波动 | 回调间隔、帧龄、目标缓冲 |
| 随机丢包 | 1% / 3% | SDK 交付空洞与应用播放行为 |
| 突发中断及恢复 | 短时断流，随后恢复 | 尾音、重新预缓冲、队满和会话恢复 |

每档重复相同语句和操作，分别记录上下行。电脑热点即使未开启注入，也需单独测正常基线；记录热点上联网与设备侧的实际频段。

重点确认：

1. 抖动增大时目标缓冲上升，保持在 60–500 ms；稳定后按策略逐步下降。
2. 时间戳稳定、预热满足后，低/高水位分别进入 319/321 点消费档，恢复后回到 320。
3. 分开记录包到达、队列驻留、待写 PCM、锁等待和写失败；I2S 输出水位估算不是真实 DMA 游标。
4. 静音、停止和会话切换后没有旧代次音频串入，短句尾字完整。

录音至少包含近场/远场、轻声/正常声、播放时双讲、快速“123456”和句末字。
对比原始采集、AFE 后、发送前及远端录音，找到第一处变化再调参。参数与资源预算见[音频链路](音频与资源.md)。
