# 已知限制与兼容性

首次操作见[开发指南](docs/GETTING_STARTED_CN.md)。本页说明 CoreS3-SE 的部署条件、数据兼容性和性能边界。

## 网络与凭据

默认服务发现使用 HTTP，后续使用发现服务返回的地址。当前方案不提供全链路 TLS 认证，ESP-IDF 证书包也不会自动保护 SDK 的自研 HTTP 链路。随附 TiRTC 2.5.0 库的 `httpclt.o` 未引用 TLS 客户端函数；本轮未验证 SDK 的 HTTPS 能力，不能沿用旧库的证书认证结论，也不能仅改 URL 就视为安全升级。

因此，当前默认方案仅适合受控网络评估：令牌、设备凭据和控制消息可能被窃听或篡改。生产部署需分别处理服务发现、API、MQTT 和 SDK 的传输认证。热点配网无密码，应限制开放环境与时间；分享日志前删除密码、token 和设备密钥。

## 配网与版本迁移

Wi-Fi 配置保存在 `wifi_cfg/credentials`，为一条 99 字节记录：格式版本 1 字节、SSID 33 字节、密码 65 字节。

历史网络另存于 `wifi_cfg/known`，为版本化的 492 字节记录，最多保留最近 5 个成功获得 IP 的网络。它不改变当前启动凭据，也不自动轮换多个历史网络重连。旧固件已有的单组凭据在升级后首次联网成功时进入历史；无法恢复旧固件未记录过的其他网络。删除 Wi-Fi 配置会一并清除历史。

保存的密码只在设备内复用，不通过配网页接口返回；这不等于 NVS 加密，也不改变开放热点和 HTTP 的传输边界。扫描只列出 2.4 GHz 网络，隐藏网络需手动填写；不支持的加密方式会禁用点选。

| 情况 | 处理方式 |
| --- | --- |
| 只有旧版 `ssid/password` | 新版可读取；下次保存写成新记录，保留旧键 |
| 新记录损坏或版本未知 | 返回错误，不回退到旧网络 |
| 写入或提交返回错误 | 完整新记录可能已落盘；先检查设备状态，不能假定 Flash 已回滚 |
| 保存成功但连不上网络 | 保存成功不等于密码正确，仍需检查 Wi-Fi 认证 |
| 回退到只认识旧格式的固件 | 可能读到旧网络，需在旧固件中重新配网 |
| 手机关闭配网页 | 不撤销已经接纳的保存和重启 |

重启由常驻内部栈任务处理；任务不可用、已有重启请求或存储失败时，接口返回错误。真实写入中断仍受 NVS 恢复机制约束，主机模拟不能证明设备掉电恢复已经通过。

## 音频与交互

| 项目 | 当前边界 |
| --- | --- |
| 多业务 | AI、H5、设备、微信通话和多人对讲共用音频，通过会话状态机仲裁 |
| 麦克风 | 第一麦与 MIC3 电气回采进入官方单麦 FD AFE（AEC + NLP）；第二麦只采集电平用于诊断，当前没有双麦增益。此前的双麦配置已实测与本配置输出逐样本相同 |
| 采集丢块 | 输入池满、AFE 环满或读失败的块会计数（`AT+STATUS` 的 `AFE drop`），并在下一帧标记；预录、上行时间轴和唤醒窗口在该处断开，不做静音补偿 |
| 抖动缓冲 | 初始 200 ms，范围 60–500 ms，32 槽固定池；持续断流或队满仍会影响播放 |
| 播放调速 | 每 20 ms 输出 320 点，消费 319/320/321 点，约 ±0.3125%；不是保音高时间伸缩，也不能补回丢失数据 |
| 唤醒与双讲 | 距离、语速、噪声、房间反射和播放音量都会影响效果，需实录确认 |
| 字幕 | 显示最新两行，不保存完整历史；无朗读位置时不提供逐字同步分页 |
| 表情 | 变化依赖云端事件，不保证每段话都有新的表情 |
| 绑定提示音 | 有效确认可取消后续播报；下载中的取消仍受下载返回时机约束 |

排查卡顿时分别看 Wi-Fi、SDK 回调、播放队列和 I2S 写入。软件队列为空不等于 DAC 欠载，最终听感仍需录音确认。

## H5 双向语音

CoreS3-SE 没有摄像头，不初始化摄像头、不声明视频能力，也不发送或订阅视频流。
H5 使用 PCMA 8 kHz 单声道；设备发送音频流 10，接收音频流 14，发送受订阅和会话代次控制。
采集及 AFE 在 16 kHz 工作，上行降采样、下行升采样后复用同一播放链路。

本轮真机覆盖已由用户确认通过，不沿用原立创 S3 的摄像头测试作为本板证据。
用户反馈未附新的录音、弱网参数或长稳时长；设备发送成功也不能单独证明双向听感。
使用步骤见[H5 查看与对讲](docs/GETTING_STARTED_CN.md#h5-查看与对讲)。

## 取消设备拨号

拨号请求返回房间号前挂断，设备仍保留这次请求的归属；迟到的房间会被取消或挂断，
再查询服务端确认清理完成。实际 HTTP 错误、提交失败或未知结果不会被当作成功。

每条记录最多提交 6 次清理请求，失败后保留记录并报告错误；未清理的记录会阻止 H5 接入。
同时最多保留 4 条拨号记录，记录用尽时拒绝提交新设备拨号。该边界避免未知房间影响下一通，
没有通过无限重试或超时清状态伪装恢复。服务器长期不可达时需要检查失败日志和服务端房间状态。
绑定身份变化会使旧身份记录失效，普通 MQTT 重连不会清除它们。

```text
third_party/tirtc/lib/libTiRTC.a
TiRTC: 2.5.0 (v2.5.0-9088239c)
size: 8714728 bytes
SHA-256: 7334e846ed4261b5297607c85acafe1d586a22374f7c8e37b102b2742e47c7aa
```

包身份与逐文件校验见 [VERSION.md](third_party/tirtc/VERSION.md) 和
[SHA256SUMS.txt](third_party/tirtc/SHA256SUMS.txt)。SDK 同时保留 TGTRP 与 KCP
传输路径，实际使用哪一种取决于会话协商；Build Info 或双方版本相同不能代替协议日志。

更换源码、SDK、模型或配置后，重新构建并验证受影响路径。同一版本号不能区分未提交改动；报告问题时同时记录 commit、工作树状态和设备 ELF 身份。
