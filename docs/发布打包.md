# 发布打包

[文档地图](README.md) · [开发指南](开发指南.md) · [第一次编译](第一次编译.md)

**给谁看**：要把自己编的固件打成发布包的维护者。只是使用或日常开发，用不到这一篇。

**读完能做到**：把一个或多个产品的构建目录打成带完整镜像、清单和校验和的发布目录。

## 1. 定版本号

固件的版本号只有一处：`cmake/esp-idf-product/CMakeLists.txt` 里的 `PROJECT_VER`。它编进固件，串口和界面上显示的就是它。

开发期间写成 `0.3.2-dev` 这样的形式。发布时改成 `0.3.2` 或 `0.3.2-rc.1`，提交，然后重新编译要发布的产品。

发布的固件统一用一条 ESP-IDF 线编译：`components/tirtc_sdk/packages.json` 的 `release_line`，现在是 6.1。编译时加 `--idf 6.1`，产物在 `build/<产品名>/sdk-firmware-idf6.1/`。

## 2. 打包

```bash
python scripts/package_release.py --version 0.3.2-rc.1 --out releases/v0.3.2-rc.1 \
    --level xiaotai-szpi-s3=A --level xiaotai-cores3-lite=A \
    build/xiaotai-szpi-s3/sdk-firmware-idf6.1 build/xiaotai-cores3-lite/sdk-firmware-idf6.1
```

发布目录里有这些文件：

| 文件 | 内容 |
| --- | --- |
| `v<版本>_<开发板>_merged.bin` | 每块开发板一个完整镜像，从 `0x0` 写入。只合并到最后一段数据，不填满整片 Flash。`<开发板>` 和对外显示的名字写在板包里，见下面“开发板的发布名”。GitHub 会改掉附件名里的中文，所以文件名用英文，上传时用清单里的 `label` 作附件的显示名：`gh release create … "<文件>#<label>"` |
| `release-manifest.json` | 每块板的 `slug`、`model`、板卡、芯片版本范围、分区表、ESP-IDF、SDK、配置和 ELF 的哈希、验证等级 |
| `xiaotai-v<版本>-flashing-guide.md` | 烧录说明 |
| `xiaotai-v<版本>-release-notes.md` | 发布说明，取自 `CHANGELOG.md` 里对应版本的一节 |
| `SHA256SUMS.txt` | 各文件的校验和 |

文件名都是 ASCII。同样的输入打出来的包逐字节相同。

### 开发板的发布名

`board.json` 的 `identity.release` 写这块板发布时叫什么：

```json
"release": {"slug": "lckfb-esp32s3", "model": "立创实战派开发板 · ESP32-S3", "file": "lckfb-esp32s3"}
```

| 字段 | 用在哪 |
| --- | --- |
| `slug` | 下载页上这块板的标识，写进清单 |
| `model` | 读者看到的型号名：发布说明和烧录说明的标题、附件的显示名 |
| `file` | 文件名里的 `<开发板>`：`v0.5.0_lckfb-esp32s3_merged.bin` |

`slug` 和 `file` 只用小写字母、数字、`-` 和 `.`，各板不能重名。发布过的名字不再改，下载页和别人的脚本按它找文件。

## 3. 打包前的检查

工具会逐项检查，有一项不对就停下，不写任何文件：

- 每个构建用到的仓库文件都和 `--commit`（默认 `HEAD`）里的一致，没有未提交的改动，也没有仓库外多出来的源文件。
- 构建之后镜像没有被改过，ELF 正是应用镜像里记录的那个，固件里的版本号等于 `--version`。
- 镜像头里的芯片和 Flash 容量、分区表校验和都正确，应用分区放得下应用。
- 产品确实属于该板的 `board.json`；正式版本要求 `CHANGELOG.md` 里这一节已经去掉“未发布”。
- 每个构建都来自 `release_line` 那条 ESP-IDF 线，每个产品只给一次；板包写了 `identity.release`。

## 4. 验证等级

| 等级 | 含义 |
| --- | --- |
| A | 这款产品做过实机回归 |
| B | 代表板做过验证，本板完成构建 |
| C | 仅完成构建 |

没有写 `--level` 的产品算 C。C 级默认不打包，本地试打时加 `--allow-build-only`。等级只记在清单里，发布说明和烧录说明不写。

要用 ELF 解析崩溃栈时加 `--elf`，ELF 会放在 `debug/` 下留给自己用，不算发布附件；`SHA256SUMS.txt` 不列它，哈希记在清单里。
