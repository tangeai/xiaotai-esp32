# 产品选项参考

同一份 SDK 可以给不同产品保留各自的交互习惯。选项写在 `products/<产品名>/product.json`，改完要重新构建。`parameters` 选择功能行为，`options` 设置编译选项；表中用点号表示嵌套的 JSON 字段，有例外会单独标出。

| 简称 | 产品清单目录 |
| --- | --- |
| 立创 S3 | `xiaotai-szpi-s3` |
| CoreS3 | `xiaotai-cores3-lite` |
| 微雪 P4 | `xiaotai-waveshare-p4-rev3` |
| WT99 | `xiaotai-wt99p461-s1-1v1` |

“缺省”指未配置该项时的行为，“产品取值”指仓内清单的选择；写着“四款都用缺省”的选项供新产品按需开启。只对选用了对应功能的产品生效。改完用主机测试确认配置生效，再按[测试与诊断](测试与诊断.md)上板看实际效果。

## 联网与绑定

| 键名 | 缺省 | 产品取值 | 行为 |
| --- | --- | --- | --- |
| `options.NET_SCAN_TIMEOUT_MS` | `10000` ms | 两款 S3：`5000` | 限制一次 Wi-Fi 扫描的等待时间。 |
| `parameters.net.retry.steps_ms` | 未填，基础延迟从 1 秒递增至 30 秒，可另配 | 两款 S3：`[1000, 2000, 4000, 8000, 15000, 30000]` | 按表设置重试基础延迟，走到最后一项后继续用最后一档。 |
| `parameters.net.block_retry_after_driver_start_failure` | `false` | 微雪 P4、WT99：`true` | 联网驱动启动失败后暂停自动重试。 |
| `parameters.net.restrict_blocked_retry_to_recoverable` | `false` | 微雪 P4：`true` | 已暂停重试时，只在可恢复的阶段接受手动重试。 |
| `parameters.net.allow_coprocessor_info_during_maintenance` | `false` | WT99：`true` | 维护期间仍可查询协处理器 INFO；升级等操作不放行。 |
| `parameters.companion.keep_saved_wifi_on_reprovision` | `false` | 四款都用缺省 | 在设置页确认重新配网只进入配网页，不主动清除已存 Wi-Fi。显式清除命令不受影响。 |
| `parameters.binding.guest_subscribe_timeout_s` | `0`，沿用通用等待时间 | 四款都用缺省 | 临时 MQTT 订阅最多等 20 秒，也受剩余绑定有效期限制。 |
| `parameters.binding.guest_token_needs_expiry` | `false` | 四款都用缺省 | 绑定使用的临时令牌必须带有效期；已过期会被拒绝，仍有效但不足 1 秒时重新请求。 |
| `parameters.binding.resume_unbound_window_on_reconnect` | `false` | 四款都用缺省 | 断网时隐藏验证码；在原有效期内重连可继续用同一个码。 |
| `parameters.platform.reserve_unbind_signal_slot` | `false` | 四款都用缺省 | 普通信令繁忙时，仍为已授权的解绑留一个位置，不增加总容量。 |
| `parameters.environment.occupied_before_invalid_base` | `false` | 四款都用缺省 | 配网或环境切换已占用时，新的环境地址即使无效，也先报告占用。 |

## 界面与设置

| 键名 | 缺省 | 产品取值 | 行为 |
| --- | --- | --- | --- |
| `parameters.companion.binding_retry_control` | `XIAOTAI_COMPANION_BINDING_RETRY_DEFAULT` | 两款 S3：`XIAOTAI_COMPANION_BINDING_RETRY_HEADER`；微雪 P4、WT99：`XIAOTAI_COMPANION_BINDING_RETRY_REFRESH` | 绑定失败时，两款 S3 从右上角重试，两款 P4 用页面上的刷新入口。 |
| `parameters.companion.binding_guide_six_digits` | `false` | 四款都用缺省 | 绑定引导只显示六位数字验证码。 |
| `parameters.companion.save_choice_on_reselect` | `false` | 四款彩屏：`true` | 在触屏上再次确认已选的提示音或息屏时间时，也提交保存。 |
| `parameters.companion.ignore_invalid_choice_values` | `false` | 两款 S3：`true` | 忽略提示音和息屏时间的无效选值，不改当前值。 |
| `parameters.preferences.retain_maintenance_failures` | `false` | 两款 S3：`true` | 原设置写入失败尚未处理时，不接受新的维护写入。 |
| `parameters.preferences.report_invalid_packed_load` | `false` | 四款都用缺省 | 已存设置记录损坏时使用缺省值并报告 `INVALID_STATE`，不擦除或覆盖原记录。 |
| `parameters.settings.volume_accept_before_save`、`parameters.settings.speaker_accept_before_save` | 各 `false` | 两款 S3：均 `true` | 音频设备接受音量或扬声器设置后，才保存相应值。 |
| `parameters.media["output.mute_after_accept"]` | `0` | 两款 S3：`1` | 音频设备接受静音切换后，再更新软件静音状态。 |
| `parameters.companion.contacts_refresh_empty_on_confirm` | `false` | 四款都用缺省 | 已加载成功的微信联系人或申请列表为空时，可用确认键刷新；离线或维护期间不发送刷新请求。 |
| `parameters.companion.home_online_requires_transport` | `false` | 四款都用缺省 | 首页显示“在线”还要求 RTC 就绪。平台在线、RTC 未就绪时显示“连接中”。 |
| `parameters.companion.ai_talk_show_elapsed` | `false` | 四款都用缺省 | AI 对讲开始后显示本次时长，结束清零。 |
| `parameters.ui.show_start_failure` | `false` | 四款都用缺省 | 启动失败时，若首屏及所选主题可用，显示错误和本地引导。 |
| `local_on_storage_boot_failure` | `false` | 四款都用缺省 | 存储初始化出错时按缺省值本地启动并提示，禁止联网和写入，保留原记录。此键在清单顶层。 |
| `parameters.framework.reserve_owner_terminal` | `false` | 四款都用缺省 | 普通请求排满时，仍给 AI 对讲结束或超时留出通知位置，让界面能退出对讲并提示。 |

普通设置提交只保存改动的项目；写入失败仍有反馈。上表明确开启的「重选也保存」是触屏界面的例外。

## 通话与实时查看

| 键名 | 缺省 | 产品取值 | 行为 |
| --- | --- | --- | --- |
| `parameters.stream.receive_pcma_only` | `false` | 两款 S3：`true` | 实时查看按 PCMA 8 kHz 单声道接收下行，不改变其它会话的音频策略。 |
| `parameters.call.accept_peer_audio_stream` | `false` | 四款彩屏：`true` | 普通互呼可播放同一通话里对端的合法音频流；本端发送和订阅仍用流 10。 |
| `parameters.call.pause_platform_signaling_while_active` | `false` | 四款都用缺省 | 普通互呼接通后，若 3 秒内已收、发音频并写入播放，可暂停平台 MQTT 信令，单次最多 60 秒。微信、房间和振铃阶段不触发此选项。 |
| `parameters.wechat.answer_payload_requires_object` | `false` | 四款都用缺省 | 微信的 RTC 接听消息正文只接受空正文或完整 JSON 对象；不改变 MQTT 兼容行为。 |
| `parameters.wechat.custom_downlink_stream`、`parameters.wechat.downlink_stream` | `false`、`0`（关闭时忽略流号） | 四款都用缺省 | 微信只在本地接收流 0，不改变远端订阅或发送。 |
| `parameters.transport.distinguish_reported_peer_close` | `false` | 四款都用缺省 | 对讲、互呼、微信和房间诊断保留对端错误，例如 `-40008`；实时查看的正常关闭仍按正常结束处理。 |
| `parameters.transport.report_retired_open` | `false` | 微雪 P4、WT99：`true` | 已占用连接位置的入呼在撤回后沿原会话保留诊断记录，不把它算作可用连接。 |
| `parameters.stream.wait_initial_contact_confirmation` | `false` | 四款都用缺省 | 每次上线先处理设备档案、联系人和待确认请求，再开始接听实时查看。收到失败响应会记录诊断；无法发出请求时暂不接听。 |
| `parameters.transport.audio_unsubscribe_revokes_permit` | `false` | 四款都用缺省 | 对端退订当前流后立即停止该流的发送；重新授权后恢复。其它流不受影响。 |
| `parameters.media["uplink.max_queue_age_ms"]` | `0`，不限制队龄 | 四款都用缺省 | 音频上行等待满 100 ms 即丢弃并计数。 |
| `parameters.media["diagnostics.capture_window"]` | `0`，关闭 | 立创 S3：`1` | 采集诊断的 RMS、峰值和直流偏移按完整采集窗口统计。 |

`parameters.media["..."]` 中的引号内是一个完整 JSON 键。例如 `"output.mute_after_accept": 1` 直接写在 `media` 对象内。

## 房间与声音识别

| 键名 | 缺省 | 产品取值 | 行为 |
| --- | --- | --- | --- |
| `parameters.companion.room_navigation_during_environment` | `false` | 微雪 P4、WT99：`true` | 切换测试环境时仍可浏览房间页和表单，维护结束前不写入。 |
| `parameters.companion.room_full_unassigned_key_menu` | `false` | 四款都用缺省 | 未分配房间也显示完整按键菜单，确认无效项不提交操作。 |
| `parameters.room.connecting_presence` | `false` | 微雪 P4、WT99：`true` | 建立房间 RTC 之前先尝试上报“连接中”，通知失败不阻断进房。 |
| `parameters.room.wait_superseded_lease` | `false` | 两款 S3：`true` | 收到 `40921` 且无法确认上一次预约已释放时，等原预约到期。 |
| `parameters.room.recover_oversized_command` | `false` | 两款 S3：`true` | 当前房间的命令首次超过大小上限时，记录 `TIMEOUT` 并尝试重连。 |
| `parameters.room.talk_signal_before_gate` | `false` | 四款都用缺省 | 发言信令成功后才开麦。若未受理，留在房间，可再次发言。 |
| `parameters.platform.request_full_timeout` | `false` | 两款 S3：`true` | 合法普通请求遇到申请位置已满时返回 `TIMEOUT`；内存实际不足仍返回 `NO_MEM`。 |
| `parameters.recognition.legacy_four_http_slots` | `false`，申报 2 个请求位置 | 两款 S3：`true` | 声音识别可接收四个待处理 WAV 请求，第五个返回 `TIMEOUT`，不增加并发 HTTP 连接。 |
| `parameters.recognition.query_legacy_http` | `false` | 两款 S3：`true` | 识别查询总时限为 25 秒，单次网络交换上限为 20 秒，仍一次处理一条查询。 |

```sh
python scripts/sdk_selection.py --product products/xiaotai-szpi-s3/product.json
```

再按[开发指南](开发指南.md#产品选型与主机验证)跑对应产品的主机检查。
