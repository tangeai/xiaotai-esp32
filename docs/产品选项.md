# 产品选项参考

[文档地图](README.md) · [开发指南](开发指南.md) · [架构总览](架构总览.md)

**给谁看**：要调整某款产品行为的开发者。**怎么用**：按功能分组查表，找到键名，写进产品清单，重新构建。

同一份 SDK 可以给不同产品保留各自的交互习惯。选项写在 `products/<产品名>/product.json`，改完要重新构建。`parameters` 选择功能行为，`options` 设置编译选项；表中用点号表示嵌套的 JSON 字段，有例外会单独标出。

| 简称 | 产品清单目录 |
| --- | --- |
| 立创 S3 | `xiaotai-szpi-s3` |
| CoreS3 | `xiaotai-cores3-lite` |
| 微雪 P4 | `xiaotai-waveshare-p4-rev3` |
| WT99 | `xiaotai-wt99p461-s1-1v1` |
| GUITION | `xiaotai-jc1060f570c` |

“缺省”指未配置该项时的行为，“产品取值”指仓内清单的选择；写着“五款都用缺省”的选项供新产品按需开启。只对选用了对应功能的产品生效。改完用主机测试确认配置生效，再按[测试与诊断](测试与诊断.md)上板看实际效果。

## 联网与绑定

| 键名 | 缺省 | 产品取值 | 行为 |
| --- | --- | --- | --- |
| `options.NET_SCAN_TIMEOUT_MS` | `10000` ms | 两款 S3 和 GUITION：`5000` | 限制一次 Wi-Fi 扫描的等待时间。 |
| `parameters.net.retry.steps_ms` | 未填，基础延迟从 1 秒递增至 30 秒，可另配 | 两款 S3 和 GUITION：`[1000, 2000, 4000, 8000, 15000, 30000]` | 按表设置重试基础延迟，走到最后一项后继续用最后一档。 |
| `parameters.net.block_retry_after_driver_start_failure` | `false` | 微雪 P4、WT99：`true` | 联网驱动启动失败后暂停自动重试。 |
| `parameters.net.restrict_blocked_retry_to_recoverable` | `false` | 微雪 P4：`true` | 已暂停重试时，只在可恢复的阶段接受手动重试。 |
| `parameters.net.allow_coprocessor_info_during_maintenance` | `false` | WT99：`true` | 维护期间仍可查询协处理器 INFO；升级等操作不放行。 |
| `parameters.companion.keep_saved_wifi_on_reprovision` | `false` | 五款都用缺省 | 在设置页确认重新配网只进入配网页，不主动清除已存 Wi-Fi。显式清除命令不受影响。 |
| `parameters.binding.guest_subscribe_timeout_s` | `0`，沿用通用等待时间 | 五款都用缺省 | 临时 MQTT 订阅最多等 20 秒，也受剩余绑定有效期限制。 |
| `parameters.binding.guest_token_needs_expiry` | `false` | 五款都用缺省 | 绑定使用的临时令牌必须带有效期；已过期会被拒绝，仍有效但不足 1 秒时重新请求。 |
| `parameters.binding.resume_unbound_window_on_reconnect` | `false` | 五款都用缺省 | 断网时隐藏验证码；在原有效期内重连可继续用同一个码。 |
| `parameters.platform.reserve_unbind_signal_slot` | `false` | 五款都用缺省 | 普通信令繁忙时，仍为已授权的解绑留一个位置，不增加总容量。 |
| `parameters.environment.occupied_before_invalid_base` | `false` | 五款都用缺省 | 配网或环境切换已占用时，新的环境地址即使无效，也先报告占用。 |

## 视频

| 键名 | 缺省 | 产品取值 | 行为 |
| --- | --- | --- | --- |
| `parameters.video.downlink_on_demand` | `false` | GUITION：`true` | 显示对方画面要用的外部内存只在视频通话时占用，通话结束、最后一张画面收走后归还。开始前先算总量，要另外还留得下 384 KB；占不到时这一路画面先不开始、什么都不占着，每 0.5 秒再试，8 次以后每 5 秒再试。解码器连续两次要不到内存就停下归还，10 秒后再试。 |
| `parameters.video.downlink_packets` | `0`，按码流声明（H.264 为 2 秒） | GUITION：`6` | 等待解码的码流帧数上限，至少 4。 |
| `parameters.video.downlink_packet_bytes` | `0`，按码流声明（256 KB） | GUITION：`32768` | 一帧码流的字节上限，超过的丢弃；H.264 丢了就等下一个关键帧。 |
| `parameters.video.downlink_pictures` | `0`，缓冲播放 20 张，否则 3 张 | GUITION：`2` | 每块屏解好待显示的画面张数，至少 2（一张在显示，一张在写或等显示）；软件解码的输出缓冲也不超过它。 |
| `parameters.video_call.scenes[].voice_only` | `false` | GUITION：微信（`voip`）为 `true` | 这一类通话一直是语音，视频来电按语音接听。 |
| `options.VIDEO_ACCELERATORS` | 开；RGB 并口屏关 | 五款都用缺省 | 用芯片的像素加速器和硬件 JPEG 解码。RGB 并口屏由芯片从外部内存取数扫描，这两样和它抢二维 DMA 会丢像素，所以在那里用软件。 |
| `options.VIDEO_JPEG_ENCODER` | 开 | GUITION：关 | 软件 JPEG 编码。不发画面的产品可以不带。 |
| `options.VIDEO_JPEG_SOFTWARE_DECODER` | 关；RGB 并口屏开 | 五款都用缺省 | JPEG 用软件解码，给没有或不用硬件 JPEG 解码的芯片。 |

| `parameters.media["output.mute_after_accept"]` | `0` | 两款 S3 和 GUITION：`1` | 音频设备接受静音切换后，再更新软件静音状态。 |
| `parameters.companion.contacts_refresh_empty_on_confirm` | `false` | 五款都用缺省 | 已加载成功的微信联系人或申请列表为空时，可用确认键刷新；离线或维护期间不发送刷新请求。 |
| `parameters.companion.home_online_requires_transport` | `false` | 五款都用缺省 | 首页显示“在线”还要求 RTC 就绪。平台在线、RTC 未就绪时显示“连接中”。 |
| `parameters.settings.screen_brightness_default` | `100` | 五款都用缺省 | 屏幕亮度的出厂值，10–100（%），只对背光可调的板子有效；用户改过的值优先。 |
| `parameters.companion.ai_talk_show_elapsed` | `false` | 五款都用缺省 | AI 对讲开始后显示本次时长，结束清零。 |

| `options.DOOR_TEMPLATES` | 板子首屏不小于 440×300 时打开 | 由构建按板子自动选 | 门禁自己的页面、图标和字库（Flash 约 1 MB）；关掉后门禁用主题的通用页面，立创实战派 S3 就是这样。 |
| `parameters.ai_vision.user_switch` | `false` | 立创 S3、微雪 P4、WT99：`true` | AI 看图的开关存成设置 `ai_vision.enabled`，设置页和对话首页都能改；不开时开关只管到下次重启。 |
| `parameters.wake.user_switch` | `false` | 五款：`true` | 唤醒词的开关存成设置 `wake.enabled`（键 `wake_on`），设置页出现「语音唤醒」，关掉后重启仍关着；不开时没有这一行，唤醒词每次开机都打开。 |
| `parameters.ui.show_start_failure` | `false` | 五款都用缺省 | 启动失败时，若首屏及所选主题可用，显示错误和本地引导。 |
| `local_on_storage_boot_failure` | `false` | 五款都用缺省 | 存储初始化出错时按缺省值本地启动并提示，禁止联网和写入，保留原记录。此键在清单顶层。 |

普通设置提交只保存改动的项目；写入失败仍有反馈。上表明确开启的「重选也保存」是触屏界面的例外。

## 通话与实时查看

| 键名 | 缺省 | 产品取值 | 行为 |
| --- | --- | --- | --- |
| `parameters.ai_talk.opus` | `false`，用 G.711 | 五块彩屏板：`true` | AI 对讲用 Opus（16 kHz 单声道，20 ms 一包，上下行都是）。要同时打开 `options.MEDIA_CODEC_OPUS_ENCODER` 和 `options.MEDIA_CODEC_OPUS_DECODER`。服务端不接受 Opus 时，这一次对话结束，之后到重启前改用 G.711。 |
| `parameters.ai_talk.opus_heard_only` | `false` | 立创 S3、CoreS3-Lite：`true` | 收听用 Opus，发送用 G.711。解码 Opus 便宜，编码对处理器慢的板子太重。 |
| `parameters.media["playout.conceal_gap_ms"]` | `120` ms | 五款都用缺省 | Opus 下行缺口不超过这个时长时补帧：先用下一包里的纠错数据，没有就外推。`0` 关闭。 |
| `parameters.media["playout.conceal_dry_ms"]` | `40` ms | 五款都用缺省 | 接收短暂断流时最多外推这么久。`0` 关闭。 |
| `parameters.media["opus.fec"]` | `1` | 五款都用缺省 | Opus 上行编码带前向纠错，对端能用它补丢掉的包。`0` 关闭。 |
| `parameters.stream.receive_pcma_only` | `false` | 两款 S3 和 GUITION：`true` | 实时查看按 PCMA 8 kHz 单声道接收下行，不改变其它会话的音频策略。 |
| `parameters.call.accept_peer_audio_stream` | `false` | 五款：`true` | 普通互呼可播放同一通话里对端的合法音频流；本端发送和订阅仍用流 10。 |
| `parameters.call.pause_platform_signaling_while_active` | `false` | 五款都用缺省 | 普通互呼接通后，若 3 秒内已收、发音频并写入播放，可暂停平台 MQTT 信令，单次最多 60 秒。微信、房间和振铃阶段不触发此选项。 |
| `parameters.wechat.answer_payload_requires_object` | `false` | 五款都用缺省 | 微信的 RTC 接听消息正文只接受空正文或完整 JSON 对象；不改变 MQTT 兼容行为。 |
| `parameters.wechat.custom_downlink_stream`、`parameters.wechat.downlink_stream` | `false`、`0`（关闭时忽略流号） | 五款都用缺省 | 微信只在本地接收流 0，不改变远端订阅或发送。 |
| `parameters.transport.fault_restart_ms` | `0`，停到重启设备 | 五款：`5000` | RTC 传输进入故障（例如协议栈自己停了、连接释放的记录用完）后，等这么久自己重新启动；协议栈又停了就再等再来。重新上线之前不能对讲、通话和查看；重新启动和开机时一样，先让开信令，上线后恢复。`AT+LINK` 的 `wait=fault` 表示正在等。 |
| `parameters.transport.distinguish_reported_peer_close` | `false` | 五款都用缺省 | 互呼、微信、房间和还没开始的对讲在诊断里保留对端错误，例如 `-40008`；对讲中服务端离开、实时查看的正常关闭仍按正常结束处理。 |
| `parameters.transport.report_retired_open` | `false` | 微雪 P4、WT99：`true` | 已占用连接位置的入呼在撤回后沿原会话保留诊断记录，不把它算作可用连接。 |
| `parameters.stream.wait_initial_contact_confirmation` | `false` | 五款都用缺省 | 每次上线先处理设备档案、联系人和待确认请求，再开始接听实时查看。收到失败响应会记录诊断；无法发出请求时暂不接听。 |
| `parameters.transport.audio_unsubscribe_revokes_permit` | `false` | 五款都用缺省 | 对端退订当前流后立即停止该流的发送；重新授权后恢复。其它流不受影响。 |
| `parameters.media["uplink.max_queue_age_ms"]` | `0`，不限制队龄 | 五款都用缺省 | 音频上行等待满 100 ms 即丢弃并计数。 |
| `parameters.media["diagnostics.capture_window"]` | `0`，关闭 | 两款 S3 和 GUITION：`1` | 采集诊断的 RMS、峰值和直流偏移按完整采集窗口统计。 |

`parameters.media["..."]` 中的引号内是一个完整 JSON 键。例如 `"output.mute_after_accept": 1` 直接写在 `media` 对象内。

改完清单后，先预览所选组件和生效配置。例如：

```sh
python scripts/sdk_selection.py --product products/xiaotai-szpi-s3/product.json
```

再按[开发指南](开发指南.md#产品选型与主机验证)跑对应产品的主机检查。
