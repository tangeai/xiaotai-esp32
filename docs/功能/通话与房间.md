# 通话与房间

本页描述 SDK 产品上与来电取消、联网恢复有关的行为。是否有普通互呼、微信语音、房间或实时查看，以当前产品的功能选择为准。

## 来电取消与通话结束

| 场景 | 设备应有的表现 |
| --- | --- |
| 普通设备互呼还在振铃，主叫取消同一通来电 | 被叫停止铃声、退出来电页，并显示结束或取消提示。被叫不会再补发一次拒接。 |
| 同一次取消通知重复到达 | 不会再次结束会话，也不影响后来的来电。 |
| 界面或应用提交拨号后，联系人列表在请求执行前刷新或重排 | 拨号仍指向提交时的联系人，不会转拨到列表里同一位置的新联系人。受理拨号不表示对方已接通。 |

立创 S3、CoreS3 Lite、微雪 P4 与 WT99 的普通互呼可接收当前通话的合法对端音频流，原发送和订阅约定不变。两款 S3 的**实时查看下行**只接收 PCMA（G.711 A-law）；这项限制不扩展到普通互呼或微信语音。

对接原有微信信令时，设备依次读取 `wx_room_type`、`wxa_room_type`、`room_type`、`media_type` 中首个非空类型。`voice` 和 `audio` 都表示语音。字段为 `null` 或空字符串视为未提供；给了无法识别的值，不再从后面的字段兜底。

## 来电和通讯录显示的名字

| 联系人的情况 | 显示什么 |
| --- | --- |
| 你给对方设过备注 | 备注 |
| 没有备注 | 服务端给的名字，字段是 `name`，没有就取 `device_name` |
| 设备没有名字 | 「设备」和设备号的后四位 |

来电时先按联系人列表查：有名字就用它，没有才用来电信令里带来的名字。备注在串口用 `AT+CONTACT REMARK <id> <十六进制的 UTF-8>` 设置，`-` 清除，见 [AT 指令](../AT指令.md)。

## 房间断线后怎么恢复

1. 正在参与的房间因 `40300` 等房间错误停止时，平台重连或手动刷新会先确认房间归属。确认仍是原房间，才重新建媒体连接；查询临时失败时等待下一次检查，不用旧连接直接恢复。
2. 两款 S3 遇到 `40921` 且不能确认旧预约已释放时，会显示「等待旧连接释放」，等原租期到期再重连。租期内遇到一次临时心跳 `503` 不立即退房，也不会延长租期。
3. 微雪 P4 和 WT99 会在建媒体连接前尝试上报「连接中」；这次上报失败不妨碍继续连接。切换服务环境期间，两款仍可浏览房间相关页面，但创建、加入、退出和刷新不会排队执行，维护结束后再操作。

两款 S3 的当前房间会话收到超限命令时，会尝试恢复连接；同一次异常不会重复触发恢复。

验证时分开看三个时点：来电页是否退出、平台是否重新确认房间、媒体是否恢复。有串口的诊断构建可查[实际词表里的通话和房间指令](../AT指令.md#词表与权限)。单看控制台回执，无法确认对端声音或画面已经恢复。
