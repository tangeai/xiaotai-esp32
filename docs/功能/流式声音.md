# 流式声音接入

声音文件已经完整到手时，用 `xiaotai_media_play_clips()`。边接收边播放时，用 `xiaotai_media_play_stream()`。两种方式共用同一套扬声器、优先级和停止规则。流式数据由模块交给媒体引擎，不需要板包再写一套播放器。

## 声明格式

PCM16 和 G.711 A-law 已内置，无需声明。使用需要已注册解码器的编码时，在**模块的 `init`** 里声明实际会用到的编码、采样率组合。比如数据源固定发 16 kHz Opus，模块这样声明，即使扬声器的采样率不同也不需要改板包：

```c
return xiaotai_media_require_stream_format(XIAOTAI_CODEC_OPUS, 16000U);
```

流是单声道，解码器按标称 20 ms 的格式准备；每个包实际有多长，由解码器从包中读取。引擎启动时才选择和打开解码器。相同声明、同格式的已登记声音和原生输出采样率共用实例。没有注册匹配解码器，或板上不能转换到输出采样率时，`play_stream()` 返回 `XIAOTAI_ERR_NOT_SUPPORTED`，不会换一个编码播放。声明只填实际需要的组合：重复不占名额，第九种独立的有状态声明返回 `XIAOTAI_ERR_NO_MEM`；运行中不能再加声明。

## 开流、写入和结束

1. 将声明的 `encoding` 和 `rate_hz` 填进 `xiaotai_media_stream_t`，调用 `xiaotai_media_play_stream()` 取得播放 ID。明确处理 `NOT_SUPPORTED` 和 `BUSY`，不要让写入方拿无效 ID 工作。
2. 在可阻塞的工作任务调用 `xiaotai_media_play_write()`。PCM16 和 A-law 按整样本写；Opus 等帧式编码一次只写一个完整包。引擎最多缓冲 200 ms。返回 `TIMEOUT` 表示这一笔没有入队，可由调用方决定是否重试；返回 `INVALID_STATE` 则停止写入。
3. 输入结束后调用 `xiaotai_media_play_finish()`，等 `done` 确认尾部也已播放完。要提前终止，用 `xiaotai_media_stop(id)`；连续 5 秒没有写入或结束，播放器也会超时退出。

接口和错误码见 [`xiaotai/media.h`](../../sdk/xiaotai_media/include/xiaotai/media.h)。
