## 主机证据

- 本轮公共/S3 与 CoreS3、P4/WT 边界程序 43/43 通过，包含 S3 故障注入、CoreS3 MQTT 内存策略、DSI 版本适配/分配回收、WT 显示清理/SPI 诊断、构建历史归档，以及新增产品兼容契约和显式编码回归。
- 新契约程序包含 13 个测试方法：六板默认组合、36 对硬件/产品交叉组合、必需能力逐项缺失、无屏完整反馈、PCM/编码音频区分、错误显示/配置、越界路径，以及合成的无屏 PCMA/旋钮/远程输入需求。36 对中 8 对最低能力匹配、28 对被拒绝；多出的两对是两块 320×240 S3 互配，仍由实际构建入口的 `native-bound` 限制禁止换板套用源图。合成用例不代表新增板或交互实现已经可运行。
- Windows 默认 GBK 环境复现静态检查读取中文源码失败后，所有该审查路径改为显式 UTF-8；Windows 直接运行恢复通过，真实审查函数的编码回归在 Windows/WSL 均通过。
- 实际 S3 硬件所有者源码在模拟驱动下覆盖 prepare 8、audio 15、display 14 个失败点，确认回收后重入；一次删除失败保留句柄并阻止再初始化。普通与 ASan/UBSan 均通过。这不模拟真实 I2C/I2S 硬件内部状态。
- Xmini 20 项：UI/引导/命令、业务/群组/RTC、音频、USB SOF、Wi-Fi/设置/平台，以及 OLED 有界 I2C IO。普通与 ASan/UBSan 各 20/20。OLED 检查覆盖 100 ms 超时传递、线格式、失败不回调、删除失败保留资源和 1000 次创建回收。
- MZ28 11 项：微信状态/协议/消息/拒绝/连接寿命、RTC 输入与事件、音频包、BOOT、VB6824 线格式和消息缓冲。普通与 ASan/UBSan 各 11/11；SDK 回调使用原测试桩，不构成实网结果。
- Xmini 实际 Nano 源码 pending lifecycle、WHIP 输入所有权、命令发布顺序和 16 KiB 申请预算，三项普通与 ASan/UBSan 共六次通过；Mini 1347 个导出函数强制保留的交叉链接探针通过。
- 两份实际 PSA HMAC 封装与参考值一致，覆盖六个向量、非法参数、零长度输入和 4096 次密钥生命周期；WT 的实际 C61 镜像 SHA-256 校验另通过四个摘要向量、错误摘要、截断和非法输入检查。未执行更新传输。
- 实际 LVGL 9.5 软件库与小钛 draw task 接入在 ASan/UBSan 下 2/2 通过：软件回退与 RGB565 直绘在正常位置及边缘裁剪的像素相同；四块彩屏的实际键盘绘制回调均渲染全部 12 键并设置退格字体。未覆盖整套页面、PPA 硬件和触摸时序。
- 31 个迁移图片解码后 64536 个 RGB565/alpha 像素与导入时一致；这不等于整体界面已比对。
- WT 可选显示诊断的 timing、PPA、二者同时开启三种组合均用产品交叉编译参数完成实际显示模块编译。这里只是模块编译，不是额外三套固件链接，也不是 PPA 硬件验收。
- WT Hosted SPI 使用实际上游 CMake 目标验证派生源替换，再对原版和派生版 worker 运行普通/ASan/UBSan 对照：握手门控、队列、TX 所有权、传输/解码失败和 HCI/STA 分发相同，间断/重复/回绕/回退序号及九个诊断字段符合预期。模拟 IO 不证明 SPI 硬件时序。

四份 SDK 的 HTTP TLS 能力已补入契约，并在构建时检查实际 `httpclt.o` 对 Mbed TLS handshake/setup/read/write 的引用，向应用导出能力宏。P4 不再依赖旧工程的隐含宏；该检查不证明服务器证书验证正确，也不授权把 HTTPS 改成 HTTP。

本轮直接重跑的是六板整机构建、43 个主机程序、新契约与 Windows 静态检查。上列单列的 Xmini/MZ28 CTest、真实 Nano/PSA/LVGL 等专项沿用上轮固定源码的迁移基线记录，本轮未重新执行；对应业务/媒体/UI/驱动和 SDK 没有改动。不能把沿用证据写成新增运行结果。

复现入口：`tests/run_host.py`、`tests/host_crypto/run.py`，以及 `tests/xmini`、`tests/mz28`、`tests/lvgl` 的 CMake/CTest 工程。主机需具备 C/C++ 编译器、CMake 和 Ninja；后面三项在 Linux 主机运行，可开启 `XIAOTAI_SANITIZERS`。
