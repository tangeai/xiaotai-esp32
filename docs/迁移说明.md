# 从 v0.2 升级到 v0.3

[返回首页](../README.md) · [开发指南](开发指南.md) · [新板接入](新板接入.md) · [AT 指令](AT指令.md)

v0.3 把板级适配、产品选型和共享应用彻底分开，只保留一个构建入口。已经烧到设备上的固件不会随源码更新；日常使用照旧按[快速开始](快速开始.md)选发布包。

## 一眼看懂变了什么

| 项目 | v0.2 | v0.3 |
| --- | --- | --- |
| 构建入口 | 原入口（`main/` + 根 `CMakeLists.txt`）和 SDK 入口两套，`--entry` 选择 | 只有 SDK 入口：`python scripts/build.py <板>`；`--entry legacy` 直接报错 |
| 代码位置 | 板级代码和业务混在 `main/` 下 | `boards/` 写硬件事实，`products/` 选功能，`sdk/` 和 `apps/` 放共享实现 |
| ESP-IDF | 6.0.2 为主，立创 S3 用 6.0.3；可选 5.5.5 | 四款统一 6.0.3（按官方提交核对）；可选 5.5.5 |
| TiRTC | 仓库里存放的验证库和 2.6.0 官方包 | 官方 2.6.3，构建时从官网下载（`scripts/fetch_tirtc.py`） |
| 产物目录 | `build/<产品>/firmware/`、`firmware-idf5.5/` | `build/<产品>/sdk-firmware/`、`sdk-firmware-idf5.5/` |
| 应用镜像名 | `xiaotai.bin` | 按产品命名，例如 `xiaotai_szpi_s3.bin` |
| 版本号 | 根 `CMakeLists.txt` | `cmake/esp-idf-product/CMakeLists.txt` 的 `PROJECT_VER` |
| 打包 | 只认 `firmware*` 目录 | `scripts/package_release.py` 直接打包 `sdk-firmware*` 目录 |

## 命令对照

| 想做的事 | v0.3 的命令 |
| --- | --- |
| 编立创实战派 S3 | `python scripts/build.py lckfb/szpi-esp32s3` |
| 编 CoreS3-Lite | `python scripts/build.py m5stack/core-s3` |
| 编微雪 P4 3.5（rev3） | `python scripts/build.py waveshare/esp32-p4-wifi6-touch-lcd-3.5` |
| 编 WT99P461-S1 | `python scripts/build.py wt99p461-s1` |
| 用 ESP-IDF 5.5 | 同一命令加 `--idf 5.5` |
| 换功能组合 | 同一命令加 `--variant <名称>`，名称见 `products/<产品>/product.json` 的 `variants` |
| 只看配置不编译 | 加 `--dry-run` |
| 预先准备 TiRTC 库 | `python scripts/fetch_tirtc.py --all` |

两款 P4 只支持芯片修订 rev3.01 及以上（rev1.x 不能用）。

## 代码怎么迁

| v0.2 里改的地方 | v0.3 改哪里 |
| --- | --- |
| `main/boards/<板>/` 的引脚、外设初始化 | `boards/<厂商>/<板>/board.json`（硬件事实）和 `board.cc`（创建零件） |
| `main/boards/<板>/sdkconfig.*` | 板目录的 `sdkconfig.board`；由能力决定的配置放在 `config/capabilities/` |
| 按板名写的功能开关 | `products/<产品>/product.json` 的 `modules`、`parameters`、`options`、`variants` |
| 业务代码（通话、房间、AI 等） | `sdk/modules/` 下对应模块 |
| 页面和交互 | 页面内容在 `apps/`，样式在 `sdk/themes/`，见技能 `xiaotai-ui` |
| 平台相关代码（存储、网络、任务） | `sdk/xiaotai_port/`、`sdk/xiaotai_net/` |

共享代码里不按板名分支：同一模块在不同产品上的差异写成 `product.json` 里的参数，由产品选值。参数一览见[产品选项](产品选项.md)，新板接入步骤见[新板接入](新板接入.md)。

## 设备上的数据

- **设置和绑定**：设置键、类型和记录布局沿用 v0.2，`nvs` 分区的位置和大小不变。从 v0.2 升级到 v0.3，配网和绑定都会保留。
- **烧录方式**：v0.2 和 v0.3 的引导程序、分区表由不同的构建生成，第一次升级时在构建目录里用 `@flash_args` 写入全部分段（不擦除 NVS），之后同一条版本线可以只写应用。
- **完整镜像**：Release 页面的 `-full-` 镜像从 `0x0` 写入，会覆盖配网和绑定，烧完要重新配网。

## 串口指令

v0.3 的 AT 指令按模块登记，`AT+HELP` 列出当前固件支持的全部指令，说明见 [AT 指令](AT指令.md)。v0.2 原入口特有的指令格式不再适用，自动化脚本请按新的回包格式改写（`tools/xt` 已更新）。
