# 小钛架构与迁移审查

开发操作入口见 [架构开发指南](架构开发指南.md)，按新增功能、硬件/交互适配和配置编译三个流程组织。本文保留迁移审查事实与差异记录。

日期：2026-11-03。对象：独立开发仓 `xiaotai-next`。本任务只在新仓和隔离验证目录修改，不向原六个工程回写，也不操作父仓索引、分支和 Tag。原工程存在其他并行更新，导入边界见文末。

## 当前结论

六板的板级、媒体、业务和 UI 已按各自 profile 接入新仓。C++ 负责固件入口、板型选择和启动结果；既有 C 状态机、实时媒体、算法、驱动及 TiRTC 接口保留。共同代码继续逐步收敛，不为了统一名称或语言改动协议和时序。

**六板原功能迁移的前期基线已完成，新增通用化标准尚未收口。** 六个默认产品均有整机编译、链接与输入/产物核验。用户进一步确认“硬件适配 + 选择现成交互/业务组合”，本轮增加真实构建契约和兼容反例检查；运行时通用端口、意图/快照映射及独立新板证明仍须完成。见 [新板适配与兼容性契约](新板适配与兼容性契约.md)。烧录、设备联网、音视频和界面对比仍属于后续阶段。

## 三个缺口的落实

| 原缺口 | 本轮实现 | 证据与未完成项 |
| --- | --- | --- |
| S3 部分初始化失败后资源残留 | [硬件所有者](../main/boards/lckfb/szpi-esp32s3/xiaotai_hardware.c) 记录 prepare/audio/display 完成状态、SPI/IO/背光所有权，失败逆序回收；清理失败保留句柄和错误，不把非空 I2C 句柄当初始化完成 | 完整编译通过；实际所有者源码在模拟驱动下通过 8/15/14 个初始化失败点及一次删除失败保留句柄检查，普通和 ASan/UBSan 均通过；硬件失败回收未验证 |
| C3 继承 S3 的 PSRAM/彩屏路径 | Xmini/MZ28 各自选择原业务、媒体和反馈组件，不进入 S3 PSRAM runtime/voice/LVGL 图；前者 PCMA 8 kHz，后者 VB6824 串口 Opus 上行/PCM 下行 | 两板完整构建、无 PSRAM/LVGL 的有效配置及主机接口检查通过；实机堆水位未验证 |
| 后续五板只有配置 | `source-profile.json` 明确 startup 和组件路径，接入原业务，专用驱动/资源归入各自所有者 | 五板均有实源，连同立创 S3 的整机构建及本轮主机回归通过；功能仍待实机验收，不以复制文件数验收 |

S3/CoreS3 的 TiRTC 预留块在任务创建前发布，创建失败仅释放未转交资源。C++ 层保留原错误和阶段，不为 C3 原有返回路径增加自动重启，也未把失败改成假成功。

## 目录与所有权

| 目录 | 职责 |
| --- | --- |
| `main/boards/<board>` | 板型、总线、接线、外设初始化与板级构建条件 |
| `main/xiaotai/application` | C++ 启动编排、C 会话状态机、进入退出与资源仲裁 |
| `services` / `transport` | 设备发现/绑定/鉴权/联系人；TiRTC 连接回收、代次与收发契约 |
| `platform` / `input` / `diagnostics` | NVS、配网、输入意图和有界诊断 |
| `media` / `ui` | 采集编码播放、AEC、唤醒、摄像头；页面手势、字幕与资源 |
| `components/tirtc_sdk` | 通用芯片包与 Xmini Mini 变体、头文件和 ABI 契约 |
| `components/xiaotai_lvgl` / `xiaotai_crypto` | LVGL 9 draw task 接入；PSA HMAC |
| `vendor` | 保留来源和许可的板型专用依赖 |

后续五板按 `cores3/p4/wt99/xmini/mz28` 子目录保持原模块边界，当前并非所有业务已合并成单一实现。每个固件只选择自己的组件，同名组件不会同时进入构建图。Board 不承担网络、身份或云服务；UART 编码音频不伪装成 I2S codec。

本轮复审确认，五个原生 profile 的 `SelectedIdentity` 主要提供板型身份，尚不是通用硬件端口实现。MZ28 startup 仍构造 UART/LED/GPIO 参数；彩屏 UI 仍持有板级初始化和媒体调用。Xmini 已有意图/快照，可作为抽取依据，但不能据此宣布六板交互已统一。现有功能保持期间，用 `native-bound` 构建限制明确标识这些边界。

## 版本迁移边界

- 固定 IDF 6.0.2/GCC 15.2.0；彩屏固定 LVGL 9.5.0/esp_lvgl_port 2.9.0。预编译算法仍需逐板验证，不能从 IDF 版本推出其兼容性。
- 31 个 RGB565+alpha 图片由 LVGL 8 交错格式转为 LVGL 9 平面格式，解码后 64536 个像素及 alpha 完全相同，字体字模保持。布局、触摸、刷新和颜色仍待实机对比。
- CoreS3 直接人脸绘制和 WT 可选 PPA 接到 LVGL 9 draw task；不支持的变换/透明度/掩码走软件绘制。PPA 原本默认关闭，未为通过构建删功能。
- P4 视频源原来已换字节，使用 `RGB565_SWAPPED`；WT 使用 `RGB565`。触摸保留 15 ms 采样。
- WT 可选 timing 日志迁为 render/flush/image-task 指标，原 LVGL 8 矩形/背景/copy 细粒度指标没有一一对应，不能称诊断字段完全相同。
- IDF 6 已包含 SPI LCD `psram_dma_direct`，不覆盖整份 IDF 5.5 LCD 驱动。Xmini 原依赖本机 IDF 的 OLED 超时扩展，由板级有界 I2C IO 承接 100 ms 超时。
- Xmini USB SOF monitor 仅替换固定 IDF 的该源文件，保留断连确认、SOF 积分和诊断，不覆盖整个 USB/VFS 组件。
- P4 保留 Hosted app-desc/SDIO 定向补丁；WT 保留 C61 SPI、SC2336 ISP 配置。补丁不适用就报错，不忽略继续。
- IDF 6 的 DSI 刷新完成使用 `on_refresh_done`，仍驱动原 VSYNC 信号量；不以颜色拷贝完成代替扫描完成。适配只生成构建目录副本，校验 esp_lvgl_port 2.9 原文件哈希。
- CoreS3 的 MQTT 1.0.0 不提供原本机扩展选项，板级构建适配仅把接收、发送和 outbox payload 分配放到 PSRAM；失败仍上报，不修改 MQTT 协议、任务或消息顺序。

## 本轮复审处理

1. 显示端口创建失败：原实现在 context 分配失败后解引用空指针，第二缓冲分配失败时尚未登记第一缓冲所有权，后期失败也未删除 LVGL display。现在立即登记自有缓冲、检查 display 创建结果，并先撤销 LVGL 对象再回收资源；失败返回 NULL，面板借出的 framebuffer 不由端口释放。实际创建/删除函数经 100 轮分配失败扫描、参数失败及共享缓冲检查，普通与 ASan/UBSan 通过。
2. WT 显示回收：原顺序先释放 LVGL 对象，DSI 回调仍可访问该对象。现在持 LVGL 锁先删除面板、停止回调，再删除 LVGL 对象；JD9165 删除失败向上传递并保留所有者，清理未完成不返回半初始化显示。真实产品函数在模拟 IO 下通过回调寿命、九处清理失败及 100 次启动回收检查，尚未做硬件故障注入。
3. CoreS3/P4/WT 房间键盘迁到 label draw task，保持退格图标字体；四板回调在实际 LVGL 9 中均渲染 12 键并命中退格标签。显示外观仍需真机比对。
4. 构建记录在新尝试前归档；后续失败不再留下上一轮成功记录冒充当前结果。产物本身不删除，历史记录可追溯。
5. WT 维护诊断适配 LVGL 9 按钮类型和 32 位坐标格式，输出字段不变；C61 APP 的 SHA-256 校验迁到 PSA，仍在镜像身份检查和传输前验证完整摘要，失败保持原 CRC 错误。实际 PSA 库通过四个摘要向量、错误摘要、截断及非法输入检查，没有执行 C61 更新。
6. WT 的 SPI 诊断原来依赖本地 Hosted 缓存改动，普通组件包缺少实际计数实现。现由板级构建生成经输入、输出哈希校验的派生源，保留原计数和输出，不修改共享缓存；原版/派生版实际 worker 的握手、TX 释放、错误路径与帧分发对照通过。见 [独立来源记录](provenance/WT-SPI诊断来源.md)。
7. CMake 把再生成输入登记为 Ninja phony 边，`ninja -t inputs` 会漏掉它们，追加 `build.ninja` 目标仍无效。现使用 CMake File API 的结构化输入清单，再合并 Ninja 构建输入和编译器头文件依赖，纳入板级生成脚本和补丁。实际 CMake/Ninja 小工程验证了该路径，包括文件名带空格的补丁；清单缺失时构建记录生成失败，不静默跳过。

## SDK 与内存

Xmini 按用户确认从原 Mini 源码隔离重编 IDF 6，保持 pending-close、命令通知顺序、16 KiB 节点申请预算及诊断 v2。见 [Mini 记录](../components/tirtc_sdk/variants/xmini/README.md)。三份通用库不覆盖。

P4 按用户后续确认采用现有新 SDK 契约：TLS 从 PSRAM/动态缓冲调整为内部 RAM/固定缓冲，并对齐 ROM MD5/RSA DS 配置。MZ28 使用通用 C3 新库，证书集合、动态缓冲、MPI/DHM 也对齐生产者。协议与业务目标未裁剪，但这些是实际内存/密码配置差异，须在硬件阶段重测，不能称内存行为已等价。

严格 crypto 契约未绕过。构建通过只表示配置匹配，不证明 TLS 安全、证书校验或堆余量合格。原 SDK `VERIFY_NONE`、Mini socket 重复 close、已有低堆/多分段风险仍未解决。

WT 的 `CONFIG_XIAOTAI_TIRTC_HTTP` 保留原工程已批准的、仅针对发现所得 TiRTC 地址的 HTTP 策略，其他发现、绑定、AI/通话服务仍保持原 HTTPS/MQTTS。新库已有 TLS 传输代码，这项旧兼容策略应在后续 HTTPS 实测及证书校验审查后重新决定，不能扩大为通用降级。SDK 连接/鉴权任务的栈水位也仍属硬件验收项。

## 复审结论与后续

1. 六板默认产品全部编译、链接通过；有效配置、依赖锁、当前自有编译输入、唯一入口、SDK 身份和 APP 空间均已复核。完整 SHA-256 见 [构建核验](构建核验.json)。
2. LVGL 9 draw task 软件路径与回退、DSI 回调选择和失败回收的主机检查通过；PPA 硬件、实际 flush/触摸时序和 S3 真实驱动失败回收仍待设备验收。
3. 本轮公共/板级回归 43 个程序通过，新增 13 项契约测试与真实审查函数的编码回归；Xmini 20 项、MZ28 11 项、真实 LVGL 两项等专项沿用固定源码的上轮记录，本轮未重跑。覆盖范围见验证文档，不能称已覆盖六板全部业务。
4. UI 直调媒体/诊断仍待按意图接口收敛；保留唤醒 token、播放 epoch、连接 generation 与原顺序，不另起第二套状态机。根据新增的新板复用要求，这一项与 typed 硬件端口、独立新板证明均为前期必需项，当前不宣布整体收口。
5. 功能项暂只接受每板原默认集。任意裁剪需同步源码、依赖、内存、能力上报和 UI。
6. 立创 S3 APP `0x4e7120`，分区 `0x500000`，仅余 `0x18ee0`（约 2%）；WT APP `0x6df430`，分区 `0x730000`，余 `0x50bd0`（约 4.4%）。后续增加功能前需先评估空间，其他板见验证表。
7. SDK 安全、许可、资源授权、设备内存/弱网/长稳独立验收。未测试不写已通过。

产品代码和用户文案用小钛表达；必要来源与版权见 [第三方记录](../THIRD_PARTY.md)。`starter_*` 是已有小钛接口，不为清理名称改动 NVS key、指纹、命令、流号、签名、绑定或连接代次。

## 导入边界

本轮迁移以导入时的 4381 文件清单和 SHA-256 为基准，附加测试、Xmini Mini 包、IDF 派生驱动及补录的 WT Hosted SPI 诊断另有来源记录。旧工程的后续字体、控制台、SDK 等改动没有自动合入新仓。

最终清单复核为 4262 个文件与导入时一致、119 个文件做了适配、缺失 0 个。该数字仅说明固定清单的来源和完整性，不代替构建或功能验收。

保护快照对比发现，立创/CoreS3/微雪/WT/Xmini 原工程分别有 8/15/11/21/6 个文件变化和 3/3/3/5/1 个新增，MZ28 未变化；父仓 `.git` 新增 12 个 object，既有文件、索引和引用未见变化。这是本轮观察到的并行状态，不能写成“原目录逐字节未变”。本任务未回滚或覆盖这些更新。后续同步应逐项审查差异，不能把新仓验证结论套到旧工程的新版本上。
