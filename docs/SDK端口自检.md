# SDK 端口台架自检

用于新 V3 固件接通后检查 ESP-IDF 端口的实际资源和时序。主机专项、源码语法检查与台架结果分开记；本文给出执行清单，不表示板载项目已经通过。

## 1. 执行前

- 按迁移阶段使用新 V3 固件。旧固件即使能连网，也不能给新端口签验收。核对产品、实际 ELF/APP、依赖与有效配置，保留回退产物；本清单不授权烧录或清除配置。
- 选获准的测试 broker/身份，停止原产品的同身份连接，避免两个相同 client ID 互相踢下线。不打印密码、Token、设备密钥或消息正文。
- 保留产品原有 MQTT/MQTTS 选择及证书校验。终端 HTTP 的约定不改写 MQTT 传输。
- 业务空闲时测量。任务、TCP 关闭状态、内部堆和最大块都要有观测来源；缺少观测手段记“未验”，不凭固定延时推断已经回收。

## 2. MQTT 生命周期

明文与 TLS 分开测，各做十轮。每轮使用 `port/mqtt.h` 的实际 `create → start → CONNECTED → stop → destroy`；配置取自测试平台，回调只复制、计数和投递，不做存储、音频或阻塞业务。

| 检查 | 方法 | 通过条件 |
| --- | --- | --- |
| 启动确认 | 启动后立即停止；另测连接尚未完成时停止 | 不误销毁尚未启动的任务，无悬挂客户端 |
| 回调归属 | 记录任务身份、回调深度；从其他任务触发发送失败和 WAKE | 只在客户端任务串行交付；错误次序保留，无递归回调 |
| 发布与确认 | 分别发 QoS0/1、NOW/QUEUE，核对真实报文号和 PUBACK | 入队成功不等于已送达；失败不留下本次幽灵记录，不误删其他待确认项 |
| 自动重连 | 保留未确认发布后使连接中断，再恢复服务 | 未确认发布沿原 ID 重传；上层重新订阅，协议确认和业务确认分开 |
| 显式停止 | 带待发/待 PUBACK 消息停止，随后启动或销毁重建 | stop 清空这些消息；不重放旧消息、不伪造 ACK；返回后无业务回调 |
| TLS 成功/失败 | 正常证书服务，以及获准的无效证书测试服务 | 正常连通，证书错误明确失败；不通过关闭校验来完成测试 |
| 资源归还 | 每轮停止、销毁后观察 MQTT 任务消失、idle 回收及 TCP 关闭状态结束 | 不再持有 socket/TLS/端口对象；保留任务栈、关闭计时和耗时证据 |

用 `xiaotai_mem_stats(XIAOTAI_MEM_INTERNAL, &stats)` 记录 `free`、`largest_block` 和水位。第一轮允许平台惰性建立全局表；以第一轮完整回收后的值为基线，后续相同周期内部空闲应归还，最大连续块不变小。测量前既要等任务被 idle 实际回收，也要等本轮连接的 TCP 关闭计时结束，不能只睡 200 ms 或估算扣掉一个 PCB。

至少保存以下记录字段，不保存鉴权内容：

```text
product,firmware_sha256,idf,mode,round,phase,elapsed_ms,internal_free,largest_block,mqtt_task_live,tcp_pending,callbacks_after_stop,result
```

公共逻辑用代表产品验证；其余只补真实的内存、RTOS/IDF 和网络实现差异，不把同一 SDK 问题强制逐板重跑。

## 3. C3 的切换门槛

平台提供且已启用 `XIAOTAI_PLATFORM_RECONNECT_COMMAND` 的开发构建，可运行：

```text
AT+PLATFORM RECONNECT 10
```

核对每轮的 `+PLATFORM-RECONNECT: round=... free=... largest=... ms=...` 及最终状态。命令不可用时先核对开发选项与实际注册，不把旧固件或主机打印冒充结果。这是 C3 的 PB1 切换前门槛，不能因为通用 PW7 板测安排在后续，就把它整体后移。

## 4. 结论

每项分别写“通过 / 失败 / 未验 / 不适用”，附固件身份、原始记录和原因。任一真实失败保留现场，沿第一处异常追责到所属层；不靠重启、改超时或隐藏错误来签字。主机的十轮循环和分配失败注入仍是离线证据，不能代替这里的 RTOS、TLS 或堆水位结果。
