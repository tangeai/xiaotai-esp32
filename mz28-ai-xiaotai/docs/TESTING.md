# 测试与验证

先按[本机使用说明书](USER_GUIDE.md)完成基本体验，再按实际改动选择回归范围。这里说明检查方法和验收标准，不把测试计划写成已经通过的结果。

## 按改动选择检查

| 修改范围 | 静态或主机检查 | 真机验证 |
| --- | --- | --- |
| 文档、链接 | 事实、反向引用、路径与锚点 | 不改变运行输入时不重新编译或烧录 |
| 配网、NVS | 请求边界、扫描/连接互斥、凭据快照与保存语义 | 错密码后更正、重复提交、重新配网和数据保留 |
| BOOT、状态灯、提示音 | 按键与状态转换；资源变更时检查 Opus 格式、哈希和构建引用 | 各阶段单击/双击、四连击、长按、响铃和结束音 |
| 联系人、VoIP 状态 | 消息所有权、方向、代次、接听/拒接/取消/挂断 | 双向发起、双方结束、第二通、重复呼叫 |
| 音频、队列、线程、内存 | 上下行格式、队列界限、回调和资源生命周期，相关主机用例 | 双向持续语音、双讲、尾音、内存水位与长通话 |
| SDK、工具链、依赖、ABI 或分区 | 核对实际输入并构建，运行全部相关主机回归 | 受影响业务、冷启动、迁移与重复操作 |
| 打包工具或发布输入筛选 | 工具自测、文件清单、许可证、ZIP 解压、哈希和链接 | 未改变运行输入时不因此重编或重刷 |

主机入口为 `tools/test_host.sh`；打包工具自测为 `tools/test_release_packaging.py`；配网页逻辑夹具为 `tools/test_wifi_portal.cjs`。环境和代码入口见[开发指南](GETTING_STARTED_CN.md)和[移植指南](PORTING.md)。

## 设备验收标准

保留现有设备身份。清 Wi-Fi、清本机绑定或完整安装的试验使用已获授权、可恢复的测试设备，不为取证擅自清除设备数据。

| 项目 | 操作 | 合格标准 |
| --- | --- | --- |
| 配网入口 | 无 Wi-Fi 开机，另测四连击 | 正确提示打开 Wi-Fi，可发现热点、打开网页，无蓝牙依赖 |
| 网络扫描 | 首次打开、连续刷新至少 5 次 | 显示真实 2.4 GHz 网络，无持续忙碌、卡死或复位 |
| 错误密码 | 错密码后再提交正确密码 | 错误凭据不落盘，不假报已保存，可重试；正确参数验证联网后保存重启 |
| 六位码绑定 | 无身份联网，填写播报码 | 数字清晰，前导零保留；授权后停止播报，断电重启保持身份 |
| 微信授权 | 添加/取消授权并刷新联系人 | 与服务端一致，无默认假数据；仅完成设备绑定不能代替微信授权 |
| 设备呼出 | BOOT 单击，微信接听 | 第一位联系人响铃，回铃正确；接通确认后才开语音 |
| 微信呼入 | 微信呼叫，BOOT 接听或双击拒接 | 来电铃声、接听和拒接均有效 |
| 取消/挂断 | 双方在振铃、建连和通话阶段分别操作 | 两端结束，无残留响铃/音频或句柄，可再次呼叫 |
| 双向语音 | 双方各连续说话至少 60 秒，含交替和同时说话 | 双方持续听见，无只通首句、严重失真或持续回放 |
| 重复呼叫 | 至少 20 轮，交替方向与取消路径 | 无死机/复位；比较相同待机状态的内存，无逐轮持续下降 |
| 长通话 | 至少 30 分钟 | 无中断、OOM、看门狗或持续积压，记录堆与任务栈最低余量 |
| 网络恢复 | 分别在空闲和通话中断网后恢复 | 错误有证据，旧会话清理后恢复上线，不假报在线 |
| 设置保留 | 分别四连击与长按 7 秒 | 前者只清 Wi-Fi，后者只清本机身份；不误称云端账号解绑 |

弱网条件按部署环境补测，每次只调整一种扰动；先证明正常网络的双向持续语音，再分别检查上下行延迟、丢包、中断及恢复。

## 关键阶段与日志

下面是日志标记的含义，不是一份已完成的真机回归记录。数字和身份以现场为准。

| 标记 | 意义 |
| --- | --- |
| `provisioning active` / `Wi-Fi scan complete` | 热点和扫描阶段；仍须用手机确认页面和真实网络列表 |
| `Wi-Fi IP ready` | 已取得 IP，平台上线仍需后续鉴权 |
| `BIND CODE` | 当前待绑定码；已有身份时不一定出现 |
| `TiRTC SYS_STARTED` / `VoIP profile ready` | RTC 与业务配置分别就绪 |
| `WHIP connected` | 传输建立，不等于微信已经接听 |
| `CONNECTED (0x2000)` | 微信确认接通，开始媒体和时长 |
| `call resources ready` | 本次通话资源清理完成 |

设备呼小程序收到本次 `call_incoming` 后立即提交 WHIP，由 `0x2000/0x2001` 确认接通/结束。微信呼入但尚未建连的取消走业务通知；不要把这两条结束路径混用。

## 结果如何记录

公开发布页的 `release-manifest.json` 记录该固件的构建与核验范围；本地交付包可另附 `VALIDATION.md`。用户确认的听感独立记为用户验收；包到达、首包或发送计数不能代替持续播放。

旧 C3 预录示例的内存和通话数据不作为 MZ28 本板依据。
